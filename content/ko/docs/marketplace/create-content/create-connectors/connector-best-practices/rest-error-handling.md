## 소개

REST 서비스를 호출할 때 오류가 발생할 수 있습니다. 오류는 다음 두 가지 유형 중 하나일 수 있습니다:

1. 응답이 있는 오류
2. 응답이 없는 오류
   
응답이 없는 경우 기본 오류 처리로 충분합니다. 이는 일반적으로 엔드포인트가 다운되었거나 타임아웃이 발생할 때 발생합니다.

응답이 있는 경우 오류 메시지에는 오류 코드와 이유가 포함되지만 메시지는 포함되지 않습니다. 따라서 응답과 함께 추가 로그 메시지를 추가한 다음 오류를 다시 throw하십시오. 로그 메시지에는 개발자에게 도움이 되는 요청에 대한 세부 정보가 포함되어야 합니다.

객체나 경로 매개변수와 같은 입력은 REST 호출에서 오류 이벤트를 트리거할 수 있습니다. 커넥터 자체에서 빈 값을 확인할 필요는 없지만, [urlEncode](/refguide/string-function-calls/#urlEncode)를 사용하기 전에 확인하십시오.

일부 상황에서는 서비스의 오류 응답에 활용하고 싶은 자체 구조가 있습니다. 예를 들어, 잘못된 요청이 있을 때 해당 메시지를 로깅하는 대신 사용자에게 다시 전달하고 싶을 수 있습니다. 그러나 하나의 Microflow에서 두 개의 다른 객체를 반환할 수 없습니다. 이러한 상황에서는 오류 메시지의 응답을 일반 메시지와 결합하십시오. 다른 모든 상황에서 오류는 예상치 못한 것이므로 오류를 반환할 수 있습니다.
