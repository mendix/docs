## 3.0.0

**Release date: March 9, 2020**

### APM이 Application Performance Diagnostics(APD)로 이름 변경

APM이 [Application Performance Diagnostics(APD)](/appstore/partner-solutions/apd/rg-three-apd/)로 이름이 변경되었습니다. 이는 기능을 더 잘 설명하고 APD가 다른 APM 솔루션과 함께 작동할 수 있기 때문입니다.

### SMART Digital Factory API

* APD는 CLEVR SMART Digital Factory의 일부이므로, SMART Digital Factory가 통계 스냅샷 및 레코딩과 같은 APD 기능을 사용할 수 있도록 API를 제공합니다.
* SMART Digital Factory 사용자의 경우, APD는 이제 CI/CD를 통해 APD 런타임 에이전트에서 단위 테스트를 실행할 수 있습니다.

### 확장성

고객 기반의 성장에 따라 APD의 아키텍처와 확장성을 개선할 필요성을 느꼈으므로 다음과 같은 개선을 수행했습니다:

* APD 브라우저 에이전트가 APM Manager에 직접 통신하는 대신 런타임 에이전트를 통해 통신하도록 재설계되었습니다. 고객 앱에 평균 10명의 사용자가 있더라도 APM Manager에 대한 연결이 10배 줄어듭니다.
* [APD Manager](https://apd.mendix.com/)의 높은 부하를 처리할 수 있도록 큐잉 메커니즘이 개선되었습니다.
* APD 데이터 정리 성능이 개선되었습니다.
* APD 런타임 에이전트에 여러 가지 소규모 개선이 이루어졌습니다.

### 지원

* 최신 Mendix 릴리스에 대한 지원을 지속적으로 추가하고 있습니다.
* APD 에이전트의 보호 장치를 개선했습니다. 이러한 보호 장치는 APD 에이전트가 너무 많은 리소스를 사용하지 않고 시스템에 과도한 영향을 미치지 않도록 하기 위한 것입니다.
* 메모리 사용량에 대한 보호 장치를 개선하여 버퍼를 지우고 에이전트를 중지하는 데 사용했습니다. 간헐적인 메모리 스파이크 시 이러한 동작이 원하지 않는 것이었으므로, 메모리 스파이크 시 중지가 아닌 일시 중지하도록 기능을 개선했습니다. APD는 10분 후 통계 수집을 재개하여 시스템이 메모리 사용 원인으로부터 복구하고 귀중한 작업을 계속할 수 있도록 합니다.

## 2.0.0

이 APM의 주요 릴리스는 클라우드, 최종 사용자 측정 및 단순성을 다룹니다.

### 클라우드 멀티테넌트

APM 2는 프로젝트 및 SSO를 위해 Mendix Portal과 통합된 멀티테넌트 클라우드 기반 앱입니다. 

APM을 사용하려면 **APMAgent2** 모듈만 설치하면 됩니다.

이 아키텍처의 주요 장점은 다음과 같습니다:

* 에이전트가 앱에 UI가 없으며 권한 및 탐색이 필요 없음
* 에이전트가 트레이스를 저장하기 위해 데이터베이스를 사용하지 않음
* 에이전트가 이미 적었던 앱에 대한 영향이 더욱 줄어듦
* 클라우드 Manager 앱의 새로운 기능이 빠르게 제공되며 앱 배포가 필요 없음

### 간소화된 UI 및 기능

APM 2는 Mendix에 맞춘 새로운 UI를 갖추고 있습니다. 전체 APM Manager App이 사용을 단순화하고 쉽게 하기 위해 개정되었습니다.

* APM을 사용하여 특정 작업을 수행하는 데 도움이 되는 투어 가이드가 추가되었습니다.
* 변경된 적이 없는 많은 설정에 적절한 기본값이 설정되었습니다.
* 일부 기술적 설정이 메모리 사용량 높음, 중간 또는 낮음과 같이 최종 사용자가 이해할 수 있는 설정으로 결합되었습니다.
* 이전 로그 도구와 트랩 도구가 로그로 결합되었습니다.
* 레코더가 즉시 저장하므로, 레코딩은 시작/중지 기능일 뿐이며 더 이상 처리가 필요하지 않습니다.

통계는 이제 액션 통계도 저장할 수 있습니다. 이를 통해 레코딩 없이도 Microflow 및 액션에 대한 상세한 인사이트를 얻을 수 있습니다. 따라서 이 옵션을 선택하면 통계를 확인하고 수정을 시작하면 됩니다!

에이전트가 더 이상 보안 및 탐색이 필요하지 않으므로 설치도 간소화되었습니다.

이제 모든 앱의 성능을 관리할 수 있는 하나의 장소인 **APM 2 Manager** 앱이 있습니다.

### 최종 사용자 측정

브라우저 측에서 성능을 측정하는 브라우저 에이전트를 추가했습니다. 이 에이전트는 통계를 수집하고 개별 트레이스를 기록할 수 있습니다. 

실제 최종 사용자 경험을 측정하면 실제 최종 사용자 경험을 파악하고 네트워크, 느린 브라우저 또는 너무 많은 데이터를 보내거나 너무 많은 요청을 하는 앱으로 인한 성능 문제를 놓치지 않을 수 있습니다.

브라우저 에이전트는 데스크톱 브라우저, 모바일 디바이스 브라우저 및 Mendix 네이티브 PhoneGap 앱에서 작동합니다.

브라우저 에이전트 통계는 이제 클릭 경로도 표시합니다. 이는 앱이 실제로 어떻게 사용되는지를 보여주는 큰 잠재력을 가진 기능의 초기 버전입니다!

### 업그레이드 참고 사항

APM 2는 APM 1과 함께 실행할 수 있습니다. 원하는 경우 나중에 APM 1을 제거할 수 있습니다.

APM 1에서 APM 2로의 데이터 마이그레이션은 없습니다.

APM 1과 비교하여 다음 APM 1 기능이 제거되었습니다:

* APM 2에는 측정 도구가 없습니다(그러나 CPU 및 메모리는 측정됨)
* APM 2에는 JVM 브라우저가 없으며 모든 JMX 노출 데이터를 측정하는 옵션을 제공하지 않습니다(이 기능은 온프레미스 상황에서 가장 가치가 있었으며 고객들이 많이 사용하지 않았습니다. 또한 이 기능은 일반 APM 솔루션에서 처리됨)
* APM 2에는 수동 쿼리를 실행하는 쿼리 도구가 없습니다
* APM 2에는 성능 트레이스에 SQL 문이 없으며 따라서 explain-plan 기능이 없습니다
* APM 2는 Java 콘솔 및 Java를 Mendix 로그로 재라우팅하지 않습니다

이러한 간소화로 인해 많은 사소한 기능이 간소화, 결합 또는 완전히 제거되었을 수 있습니다.

많은 고객이 알림을 받기를 요청했으므로 트리거에 새로운 알림 액션이 도입되었습니다. 이 액션은 **To**, **Subject**, **Message** 세 개의 문자열 매개변수가 있는 Microflow를 호출합니다. 문자열 구성을 쉽게 하기 위해 여러 대체 항목을 수행할 수 있습니다. 이 액션에 대해 로그를 기록하는 샘플 Microflow가 추가되었습니다.

### 측정 도구

* 트리거가 발생할 때마다 레코드를 저장하기 위한 Entity 트리거된 이벤트가 도입되었습니다. 이 레코드는 트리거, 측정 및 적절한 경우 트랩, 통계 스냅샷 또는 힙 덤프에 연결됩니다.
* 힙 덤프에 대한 Entity가 추가되어 클라이언트 측에서 사용할 수 있고 삭제할 수 있습니다.
* 트리거 액션에는 이제 기본 로그 외에도 이미 사용 가능한 트랩, 통계 스냅샷, 힙 덤프 및 Microflow 실행이 포함됩니다.
* GUI가 간소화되어 더 이상 대화 상자 위에 대화 상자가 없으며, 차트 보기에서 측정 및 항목 목록이 1개의 목록으로 결합되었습니다. 더 이상 접을 수 있는 패널이 필요하지 않습니다.
* 메모리를 백분율로 측정할 수 있도록 계산된 측정이 도입되었습니다.
* 결과를 계산하기 위한 표현식이 측정에 도입되었습니다.
* 표현식은 다른 측정을 매개변수로 사용할 수 있어 메모리를 총 메모리로 나누어 백분율을 얻을 수 있습니다.
* 측정을 한 번(시작 후) 실행할 수 있어 총 메모리가 한 번만 결정됩니다.
* 데이터베이스에서 검색하는 성능 문제를 방지하기 위해 이전 측정값에 대한 이력 큐가 있는 캐시가 도입되었습니다.
* 트리거 표현식은 캐시된 항목을 사용할 수 있습니다. 이전 값을 얼마나 많이 저장할지 상수로 구성할 수 있습니다.
* 또한 데이터베이스에서 이전 값 목록을 검색하여 표현식 또는 트리거 표현식에서 사용할 수 있습니다.
* 표현식을 테스트하기 위한 테스터가 도입되었습니다.
* 실행 카운터는 편집할 수 없고 보기만 가능합니다.
* 로그 또는 트랩에 대한 트리거 액션의 메시지에 이제 예를 들어 측정값이 포함된 매개변수가 포함될 수 있습니다. 

### 통계 도구

* Microflow 통계 스냅샷 Entity가 추가되었습니다. 저장된 Microflow 통계는 이제 스냅샷에 연결됩니다. 이를 통해 스냅샷을 생성하는 측정이 이 스냅샷을 열 수 있습니다. 또한 수동 스냅샷을 간단히 삭제할 수 있습니다.
* 통계 트리거가 도입되었으므로, 사용자가 Microflow에 대한 임계값을 정의하고 Microflow가 임계값보다 오래 걸릴 때 측정 도구와 동일한 액션을 수행할 수 있습니다. 고객들이 SLA 모니터링을 위해 이 기능을 요청했습니다.

### 성능 도구

* 레코딩 기능에 더 많은 공간을 제공하기 위한 새로운 레코더 탭.
* 기록된 세션 처리에 대한 보호를 무시하는 옵션. 필터링, 무시 또는 취소할 수 있는 대화 상자가 표시됩니다.
* 성능 도구에 세션이라는 새로운 Entity가 추가되어 레코딩 세션이 저장됩니다. 기록된 Microflow는 기록된 세션에 연결됩니다. 처리 후 및 성능 도구에서 트랩을 처리할 때 세션이 열려 액션의 결과를 직접 볼 수 있습니다.
* 성능 도구 필터링이 이제 반복이 많은 루프의 경우 빈 Microflow를 방지하고 더 많이 필터링하기 위해 액션 임계값에 따라 하위 Microflow를 필터링합니다.
* 성능 도구에서 트랩 처리가 간소화되어 더 이상 행을 선택할 필요가 없습니다. 완전한 트랩 또는 고급 검색에서 그리드의 전체 결과 세트가 성능 도구로 전송됩니다. 이를 통해 이 기능이 두 번의 클릭 기능이 됩니다(두 번째는 '확실합니까?').
* 성능 도구 트리 위젯에서 [+] 및 [-] 표시를 수정했습니다.
* 종료 전에 기록된 데이터를 처리하는 옵션을 제거했습니다. 거의 사용되지 않았으며 종료 지연을 유발할 수 있었습니다.
* 매개변수가 없으면 즉시 실행하도록 explain plan 대화 상자를 간소화했습니다. 매개변수가 있는 경우 상수로 대체하는 기능이 추가되었습니다.

### 쿼리 도구

* 쿼리 도구가 이제 업데이트 및 삭제를 방지합니다. JDBC에서 쿼리만 실행할 수 있습니다.
* 측정에 사용되는 쿼리는 읽기 전용이므로 측정을 손상시킬 수 없습니다.

### 로그 도구

* 로그 레벨 대화 상자에 인라인 더 보기/덜 보기 버튼이 추가되고 그리드 버튼이 줄었습니다. 이를 통해 행을 변경하지 않고 대화 상자를 닫을 때 인라인 편집이 손실되는 문제가 해결됩니다. 또한 훨씬 더 직관적이며 원하는 작업에 필요한 클릭이 줄어듭니다.

### 트랩 도구

* 옵션 대화 상자에서 별도의 탭에 제외 항목이 있습니다. 서로 위에 대화 상자가 줄어듭니다.
* 성능 도구에서 트랩을 처리하는 더 쉬운 기능. 더 이상 행을 선택하고 처리된 데이터를 직접 여는 것이 필요하지 않습니다.

### JVM 브라우저

* 'AllThreadInfo' 항목이 제거되었습니다. Mendix 6.10 및 Mendix 7에서 JVM 브라우저를 로드하는 데 5분 이상 걸렸습니다.

### 레이아웃

레이아웃이 더욱 개선되었습니다.

* 컨트롤 바의 버튼 대신 탭이 도입되었습니다.
* 더 이상 상단의 컨트롤 섹션이 없습니다.
* 성능 도구에 레코더 탭과 세션 탭이 추가되었습니다.
* 일부 경우 세부 정보 보기가 뒤로 버튼이 있는 콘텐츠 내 보기가 되었습니다(트랩 세부 정보, 스냅샷 세부 정보, 성능 도구 세션 세부 정보). 
* 왼쪽 메뉴 바가 이제 선택 후 선택된 항목을 표시합니다.
* 왼쪽 메뉴 바가 이제 도구가 실행 중인지 표시합니다.
* 왼쪽 상단의 뒤로 버튼이 제거되었습니다.
* 성능 도구를 제외한 모든 곳에서 시작/중지 버튼의 필요성을 없애는 새로운 시작/중지 대화 상자.
* 전역 설정에 데이터 정리 탭이 추가되어 다른 모든 곳에서 모두 삭제 버튼이 제거되었습니다.
* 문서에 대한 링크가 도구별 도움말 버튼으로 추가되었습니다. 대시보드에서 'i' 버튼이 문서에 연결됩니다.
* 메뉴의 녹색 '점'이 이제 도구가 실행 중인지 나타냅니다. 대부분의 장소에서 이전 배지가 제거되었습니다.

### 기타

* 로드 테스트 레코더가 권한 아래에 배치되어 일반 사용자에게 표시되지 않습니다. 이를 통해 APM에 로드 테스트 도구가 포함되어 있다는 혼란이 제거됩니다. 다른 솔루션에서 처리 및 실행할 수 있는 세션에 대한 레코더만 있습니다.

### 알려진 문제

* MySQL에 대한 JDBC 쿼리 및 explain-plan 기능은 테스트되지 않았습니다.
* 내장 데이터베이스에 대한 JDBC 쿼리 및 explain-plan 기능은 콘솔의 고급 메뉴에서 Mendix Modeler의 데이터베이스 뷰어를 시작한 후에만 작동합니다.
* 성능 도구는 레코딩 시 메모리 부족이 발생할 수 있습니다. 성능 도구에 대해 권장되는 보호 옵션은 여전히 1GB의 사용 가능한 메모리를 예상하므로, 소규모 구현에서는 보호 옵션이 더 엄격해야 합니다.
* Before Shutdown Microflow가 구성되지 않고 일부 도구가 실행 중인 경우 Mendix 애플리케이션의 종료가 약 1분 동안 중단될 수 있습니다.
* Mendix 5 이상에서 Microflow 이름은 액션 캡션에서 가져옵니다. 따라서 Mendix Modeler에서 액션 캡션이 변경되면 성능 도구의 Call Microflow 액션이 드릴다운하지 않습니다. 또한 캡션에는 Microflow 이름만 포함되고 모듈 이름은 포함되지 않으므로, 동일한 이름의 Microflow가 여러 개 있지만 다른 모듈에 있는 경우 성능 도구가 올바른 것을 선택할 수 없습니다.
* 스티키 세션이 없는 로드 밸런싱 환경에서 APM 도구는 무작위로 인스턴스에 연결되며, 이는 작동하지 않습니다! 1.6.1의 경우 APM 도구를 사용하려면 특정 서버에 대한 접근 권한이 필요합니다.
* ChartJS가 가끔 충분히 반응하지 않아 페이지를 새로 고쳐야 할 수 있습니다.
* 런타임이 중지되고 APM 콘솔이 열려 있으면 그리드 및 ChartJS의 자동 새로 고침으로 인해 오류가 나타납니다.

모든 옵션 대화 상자가 사용자 정의 설정 외에 권장 프로덕션/비프로덕션 설정을 표시하도록 재설계되었습니다.

### 간소화된 라이선스

Sandbox 및 Cloud Foundry에서 호스트 이름/IP가 변경되어 다시 시작한 후 라이선스가 유효하지 않았습니다. 클라우드 및 가상화 시대에 호스트 이름을 사용하는 것은 더 이상 유효하지 않으므로, 라이선스가 이제 프로젝트별입니다.
라이선스를 사용자에게 연결하기 위해 'CompanyName' 상수가 도입되었습니다.
로드 밸런싱 환경에서 이제 1개의 라이선스가 작동합니다. 모든 설정은 데이터베이스에서 공유됩니다.
데이터베이스 덤프를 사용할 때 라이선스가 다른 환경에서도 작동합니다. 더 이상 Modeller/Runtime 유형에 대한 의존성이 없습니다.

### 간소화된 Explain Plan 설정

JDBC 설정이 제거되었습니다. 샘플 데이터 생성 시 JDBC URL 및 explain plan 쿼리가 전역 설정에 추가됩니다. URL에 매개변수가 포함되므로 호스트 이름과 포트가 저장되지 않습니다. 이를 통해 프로덕션 데이터베이스 덤프를 로드한 후 테스트 환경에서 프로덕션 데이터베이스에 연결하는 위험 없이 사용할 수 있습니다.
쿼리가 실행될 때 매개변수가 대체되므로 설정 변경도 자동으로 처리됩니다.

### 더 빠른 시작

호스트 이름이 더 이상 필요하지 않으므로 시작이 더 빨라집니다.
또한 시작 시 더 이상 모든 JMX 데이터가 로그에 기록되지 않습니다. 이를 다시 켜고 싶은 경우 상수가 도입되었습니다.

### 가져오기 기능 제거

로그, 통계 및 성능 도구에서 로그 파일을 가져오는 기능이 제거되었습니다. 이 기능은 사용되지 않았기 때문입니다.

### 호환성

이 버전은 Mendix 6.2.0 이상만 지원합니다. Java 8에서만 가능합니다.

### 버그 수정 및 사소한 변경 사항

* 로그 레벨을 변경하고 로그 도구가 실행되고 있지 않은 경우 경고가 추가되어, 사용자가 변경 사항이 즉각적인 효과가 없다는 것을 이해할 수 있습니다.
* 측정 도구의 트리거에서 표현식에 오류가 있을 때 오류를 잡는 것이 수정되었습니다.
* Mendix 6.6+에서 설치 마법사의 유효성 검사 관련 문제가 있었습니다. 이것이 수정되었습니다.
* 성능 도구 트리의 필드 길이 관련 문제가 수정되었습니다.
* 트랩 도구가 제외 수를 다시 표시하도록 CustomString 위젯이 업데이트되었습니다.
* Modeler 경고 및 지원 중단이 제거/수정되어 개발자가 모델링할 때 APM 도구 경고/지원 중단에 방해받지 않습니다.
* 표준 Mendix 구성 요소로 기능을 대체할 수 있는 경우 특정 위젯의 사용을 제거하거나 줄였습니다.
* 트랩 도구 제외를 생성할 때 메시지 및 스택 트레이스 문자열이 이제 정규 표현식 언어의 특수 문자에 대해 이스케이프되어 즉시 테스트하고 최소 1개의 결과를 얻을 수 있습니다.
* 오류 과부하가 트랩 도구 및 전체 애플리케이션을 응답 불가 상태로 만들 수 있는 트랩 도구의 버그를 수정했습니다.
* 내장 데이터베이스에서의 explain plan 지원이 추가되었습니다.
* Mendix 7에 대비하기 위해 영구 Entity에서 비영구 Entity로 데이터를 검색하는 사용을 제거했습니다.
* 힙 덤프 기능을 별도의 보안 그룹으로 이동하여, 설치 시 이 기능을 사용할지 여부를 선택할 수 있습니다.
* 성능 도구에서 때때로 (잡힌) null 포인터가 로그에 표시되는 버그를 수정했습니다.

### 알려진 문제

MySQL에 대한 JDBC 쿼리 및 explain plan 기능은 테스트되지 않았습니다.

내장 데이터베이스에 대한 JDBC 쿼리 및 explain plan 기능은 콘솔 고급 메뉴에서 Modeler의 데이터베이스 뷰어를 시작한 후에만 작동합니다.

성능 도구는 레코딩 시 메모리 부족이 발생할 수 있습니다. 성능 도구에 대해 권장되는 보호 옵션은 여전히 1GB의 사용 가능한 메모리를 예상하므로, 소규모 구현에서는 보호 옵션이 더 엄격해야 합니다.

Before Shutdown Microflow가 구성되지 않고 일부 도구가 실행 중인 경우 Mendix 애플리케이션의 종료가 약 1분 동안 중단되는 것처럼 보일 수 있습니다.

Mendix 5 이상에서 Microflow 이름은 액션 캡션에서 가져옵니다. 따라서 Modeler에서 액션 캡션이 변경되면 성능 도구의 Call Microflow 액션이 드릴다운하지 않습니다. 또한 캡션에는 Microflow 이름만 포함되고 모듈 이름은 포함되지 않으므로, 동일한 이름의 Microflow가 여러 개 있지만 다른 모듈에 있는 경우 성능 도구가 올바른 것을 선택할 수 없습니다.

스티키 세션이 없는 로드 밸런싱 환경에서 APM 도구는 무작위로 인스턴스에 연결되며, 이는 작동하지 않습니다! 1.6.1의 경우 APM 도구를 사용하려면 특정 서버에 대한 접근 권한이 필요합니다!

## 1.6.0

이 버전의 테마는 Mendix 6 및 Mendix World에서 보여줄 Microflow 통계의 시각적 추세입니다.

### 새로운 기능: Microflow 통계에 추세를 보여주는 그래프

Microflow 통계의 이력에서 추세를 더 잘 시각화하고 보여주기 위해 최근 100개의 통계를 보여주는 그래프가 추가되었습니다. 통계 도구에서 [History] 버튼과 Microflow 이력(검색 메뉴 아래)에서 [Show History Graph] 버튼이 Microflow 통계에 대한 그래프(추세 시각화용)를 표시합니다.

{{< figure src="/attachments/releasenotes/add-ons/apd/apm-1/apm-1.6/Microflow_Trend.png" class="no-border" >}}

이 기능을 사용하면 성능 분석 중에 특정 기간 후 Microflow가 실행하는 데 더 많은 시간이 걸리는지 확인할 수 있습니다. 이는 데이터베이스 테이블이 채워지고 있음을 나타낼 수 있습니다.

### 새로운 베타 기능: Microflow 통계에 대한 트리거

고객들이 Microflow가 특정 시간보다 오래 실행될 때 알림을 받기를 요청했습니다. 빠른(베타) 구현은 쿼리 도구에서 Microflow 통계를 수집하고 이를 측정으로 사용하는 것이었습니다. 그런 다음 Microflow 통계의 측정에 대한 트리거를 구축하여 예를 들어 이메일을 보낼 수 있습니다.
이 기능은 향후 변경될 예정입니다.

### 새로운 기능: OData를 통한 보고 지원

APM 도구에 이제 OData 소스가 있어 사용자가 APM 도구로 수집된 데이터에 대해 자체 보고를 사용할 수 있습니다. OData 소스에는 별도의 권한이 있어 이 기능의 사용 여부를 구성할 수 있습니다.

### 새로운 기능: 로드 테스트 레코더

CLEVR에는 컨설턴트가 프로젝트에서 사용할 수 있는 로드 테스트 도구가 있습니다. 이 도구는 향후 제품화될 가능성이 있으며 APM 도구에 포함되어 있지 않습니다. 이 도구는 세션을 기록하기 위한 레코더가 필요합니다. 이러한 세션은 로드 테스트에서 사용하기 위해 스크립트/매개변수화될 수 있습니다.
APM 도구에 이제 로드 테스트 레코더가 포함되어 APM 도구 사용자가 즉시 로드 테스트를 준비할 수 있으며 앱에 모듈을 다시 추가할 필요가 없습니다.
로드 테스트 고객은 측정을 위해 APM 도구가 필요하므로 이 추가의 혜택을 받습니다.
이 기능은 추가 도구 메뉴에서 볼 수 있습니다.

### 새로운 기능: 특정 기간 후 데이터 정리

측정 도구는 시간이 지남에 따라 데이터베이스가 커지게 합니다. 이 도구에는 공간 부족에 대한 보호 기능이 없었습니다. 이러한 이유로 지정된 시간 후 자동 데이터 제거가 구축되었습니다.
모듈별로 특정 일수 후 데이터를 제거하도록 구성할 수 있습니다. 기본값:

* 로그/트랩 도구 기본 100일
* 통계 도구 이력 365일
* 성능 도구 데이터 30일
* 측정 도구 7일, 메트릭별 구성 가능.
    * 더 이상 측정되지 않는(따라서 구성이 없는) 메트릭은 데이터베이스에서 100일 후 삭제됩니다. 이는 구성할 수 없습니다.
* 수동 쿼리 감사, 365일. 감사가 조작되지 않도록 하기 위해 구성할 수 없습니다.

### 호환성, 버그 수정 및 사소한 변경 사항

이 버전은 Mendix 6.2.0 이상만 지원합니다. Java 8에서만 가능합니다.

* 통계 도구가 로그아웃 시 로깅에 파싱 오류를 발생시켰습니다. 사용자에게는 실제로 보이지 않지만 경고에 대해 트래핑하면 트랩이 생성됩니다. 이제 수정되어 로그아웃도 통계에 포함됩니다.
* 설치 중 Mendix가 다른 Mendix 버전에서 Java에서 다른 매개변수 이름을 생성하기 때문에 시작 시 오류가 발생하는 경우가 있었습니다. 때로는 'FileName'이 허용되었고 때로는 허용되지 않아 Java에서 'FileNameParameter1'이 됩니다. 이러한 설치 오류를 방지하기 위해 3개의 가져오기 Java 액션에서 'FileName'이 포함된 매개변수 이름이 'FileNameParameter'로 변경되었습니다. 또한 Java 액션 ExecuteMicroflowAsync에서 매개변수 'MicroflowName'이 'MicroflowNameParameter'로 변경되었습니다.
* 성능 도구 세부 정보의 Mendix 6 버전 그리드가 루프 반복에 대해 정렬할 수 있도록 변경되었습니다.
* 설치 중 샘플 데이터를 선택하면 이제 MySQL용 explain plan 샘플 데이터도 추가됩니다.

### 알려진 문제

MySQL에 대한 JDBC 쿼리 및 explain plan 기능은 테스트되지 않았습니다.

내장 데이터베이스에 대한 JDBC 쿼리 및 explain plan 기능은 작동하지 않습니다.

성능 도구는 레코딩 시 메모리 부족이 발생할 수 있습니다. 성능 도구에 대해 권장되는 보호 옵션은 여전히 1GB의 사용 가능한 메모리를 예상하므로, 소규모 구현에서는 보호 옵션이 더 엄격해야 합니다.

Before Shutdown Microflow가 구성되지 않고 일부 도구가 실행 중인 경우 Mendix 애플리케이션의 종료가 약 1분 동안 중단되는 것처럼 보일 수 있습니다.

Mendix 5 이상에서 Microflow 이름은 액션 캡션에서 가져옵니다. 따라서 Modeler에서 액션 캡션이 변경되면 성능 도구의 Call Microflow 액션이 드릴다운하지 않습니다. 또한 캡션에는 Microflow 이름만 포함되고 모듈 이름은 포함되지 않으므로, 동일한 이름의 Microflow가 여러 개 있지만 다른 모듈에 있는 경우 성능 도구가 올바른 것을 선택할 수 없습니다.

Mendix 6.2.0에서 CustomString 위젯이 렌더링되지 않습니다. Mendix Marketplace의 최신 버전으로 이 문제를 해결할 수 있습니다.

Sandbox 또는 Cloud Foundry에서 인스턴스는 매번 별도의 호스트 이름/IP를 갖게 됩니다. 라이선스는 다시 시작한 후 작동하지 않습니다. 이것은 1.7.0에서 수정되었습니다.
