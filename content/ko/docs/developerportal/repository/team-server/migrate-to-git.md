## 소개

Scrum Master는 SVN 버전 제어 시스템에서 Git으로 앱을 마이그레이션할 수 있습니다. 버전 제어에 대한 자세한 내용은 *Studio Pro 가이드*의 [버전 제어](/refguide/version-control/)를 참조하세요.

Git은 SVN에 비해 여러 가지 장점이 있는 최신 버전 제어 시스템입니다. 자세한 내용은 [버전 제어 FAQ](/refguide/version-control-faq/)를 참조하세요.

메인 라인이 Studio Pro 버전 9.24.28 이상이고 팀 역할이 Scrum Master인 경우, 앱의 **Team Server** 페이지 상단에 마이그레이션 가능 알림이 표시됩니다. **Migrate to Git**을 클릭하여 마이그레이션 적격성을 확인하고 마이그레이션을 시작하세요.

## SVN에서 Git으로 마이그레이션 시기

Mendix는 Git으로의 마이그레이션을 Studio Pro 버전 10.24 LTS로의 업그레이드와 함께 수행할 것을 권장합니다. Studio Pro 버전 9에서의 Git 장점은 제한적이기 때문입니다. 이 권장 사항에 대한 자세한 내용은 *리포지토리 크기 문제 해결*의 [Git 문제 방지 권장 사항](/refguide10/troubleshoot-repository-size/#recommendation) 섹션을 참조하세요.

## 마이그레이션 적격 앱

{{% alert type="info" %}}

Scrum Master 역할을 가진 사용자만 앱을 마이그레이션할 수 있습니다. 자세한 내용은 [앱 역할](/developerportal/general/app-roles/)을 참조하세요.

{{% /alert %}}

Git으로 마이그레이션하려면 앱이 여러 기준을 충족해야 합니다. 자동 적격성 검사는 아래에 언급된 기준을 충족하는지 확인하고, Git 브랜치 명명 규칙 등 특정 기술적 측면에서 SVN 리포지토리를 검사합니다. 리포지토리 크기에 따라 검사에 몇 분이 걸릴 수 있습니다.

다음 기준에 따라 앱이 Git으로 마이그레이션될 수 있는지 결정됩니다:

* 앱의 메인 라인('main') 브랜치가 Studio Pro 버전 9.24.28 이상
* 앱의 모든 브랜치가 Studio Pro 버전 9.12 이상
* 현재 버전 제어가 Team Server SVN
* 최신 리비전의 *mpr* 파일 크기가 400 MB 미만

위에 언급된 필수 기준 외에도 버전 제어 이력을 마이그레이션할 수 있는지 확인하는 검사가 수행됩니다. 이력 마이그레이션 자격을 갖추려면 전체 SVN 리포지토리 크기가 3.5 GB 미만이어야 합니다.

{{% alert type="info" %}}

적격성 검사는 리포지토리 크기를 표시하지 않으며, 지원 엔지니어도 이 정보에 접근할 수 없습니다. 또한 SVN이 데이터를 관리하는 방식으로 인해 브랜치를 삭제해도 서버 측 리포지토리 크기가 줄어들지 않습니다.

{{% /alert %}}

### 적격성 검사 결과

#### 이력 포함 마이그레이션 가능

리포지토리가 전체 이력 포함 마이그레이션에 적격한 경우, 마이그레이션 중 이력을 유지할지 여부를 선택할 수 있습니다.

{{% alert color="info" %}}

마이그레이션 후 가장 원활한 경험을 위해 Mendix는 [이력 없이 마이그레이션](#without-history)할 것을 권장합니다.

{{% /alert %}}

#### 이력 없이 마이그레이션 가능

앱이 마이그레이션에 적격하지만 SVN 리포지토리 크기가 임계값을 초과하는 경우, 메인 브랜치의 최신 커밋만 마이그레이션할 수 있습니다. 이 제한은 마이그레이션 후 원활한 경험을 보장하기 위해 부과되었으며, [대용량 Git 리포지토리 크기](/refguide/troubleshoot-repository-size/)는 개발자 경험에 부정적인 영향을 미칠 수 있습니다.

{{% alert type="info" %}}

마이그레이션 완료 후 SVN 리포지토리의 전체 백업을 받게 됩니다.

{{% /alert %}}

프로세스에 대한 자세한 내용은 아래의 [이력 없이 마이그레이션](#without-history) 섹션을 참조하세요.

#### 마이그레이션 부적격

앱이 마이그레이션에 적격하지 않은 경우 이유가 페이지에 나열됩니다. 프로세스를 계속하려면 이러한 이유를 해결하고 다시 시도하세요.

##### MPR 파일 크기

*.mpr* 파일의 크기가 임계값을 초과하면 Git으로 마이그레이션 후 급격한 리포지토리 성장을 방지하기 위해 마이그레이션이 차단됩니다. 앱의 마이그레이션 승인을 받으려면 지원팀 또는 Customer Success Manager와 다음 단계에 동의해야 합니다:

1. [이력 없이 마이그레이션](#without-history). 유지하려는 모든 브랜치를 통합해야 합니다.
2. 앱을 Studio Pro 버전 10.24 LTS로 업데이트하여 자동으로 [MPRv2](/refguide10/troubleshoot-repository-size/#mprv2)로 변환합니다.
3. [Git 정리](/refguide/troubleshoot-repository-size/#cleanup-tool)를 실행합니다.

처음 두 단계는 짧은 시간 내에 실행해야 합니다. 마지막 단계는 기술적으로 선택 사항이지만, 최상의 경험을 위해 강력히 권장됩니다.

## 마이그레이션 작동 방식

계속하기로 선택하면 앱이 영구적으로 Git으로 마이그레이션되며, 마이그레이션은 되돌릴 수 없습니다. 이력 포함 여부에 따라 프로세스가 다릅니다. 자세한 내용은 이 페이지의 관련 섹션을 참조하세요.

마이그레이션이 시작되면 SVN에 대한 접근이 즉시 비활성화되어 개발자가 복사되지 않을 SVN 변경 사항을 만드는 것을 방지합니다. 어떤 이유로든 마이그레이션이 실패하면 롤백되고 SVN에 대한 접근이 복원됩니다.

팀 멤버에게 프로세스를 알리기 위해 두 개의 이메일이 자동으로 발송됩니다:

* 마이그레이션 시작
* 마이그레이션 완료 또는 마이그레이션 실패

이러한 이메일은 단계에 대한 간략한 정보를 제공하며, 마이그레이션 중에 이루어진 변경 사항은 더 이상 SVN에 커밋할 수 없으므로 손실될 것임을 강조합니다.

### 이력 없이 마이그레이션 {#without-history}

이력 없이 마이그레이션하는 동안 메인 브랜치의 마지막 리비전만 SVN에서 Git으로 복사됩니다.

마이그레이션은 완료하는 데 몇 분이 소요됩니다.

마이그레이션이 완료된 후 SVN 리포지토리의 전체 백업이 생성되어 90일 동안 모든 Scrum Master에게 제공됩니다. 백업을 다운로드하는 방법에 대한 정보가 포함된 이메일을 받게 됩니다. 이 백업이 만료되기 며칠 전에 앱의 모든 Scrum Master에게 또 다른 이메일이 발송됩니다.

{{% alert color="info" %}}

마이그레이션을 시작하기 전에 팀 멤버에게 변경 사항을 커밋하고 메인 라인에 병합하도록 알려주세요.

{{% /alert %}}

{{% alert color="warning" %}}

메인 브랜치에 병합되지 않은 작업은 Git 리포지토리로 마이그레이션되지 않습니다.

{{% /alert %}}

#### SVN 백업 사용

모든 Scrum Master는 SVN 백업을 다운로드할 수 있는 링크가 포함된 이메일을 받습니다. 백업은 `https://git-migration.home.mendix.com/p/view-backup/[repository-ID]`를 통해서도 접근할 수 있으며, *[repository-ID]*를 채워야 합니다.

그런 다음 *[repository-id].dump* 파일을 로컬 장치에 다운로드하고 이 파일을 사용하여 리포지토리를 로컬에서 복원할 수 있습니다.

{{% alert color="warning" %}}

SVN 백업은 90일 후 자동으로 만료됩니다. 이 시간이 지나면 SVN 이력은 영구적으로 삭제되며 복구할 수 없습니다.

{{% /alert %}}

로컬 SVN 리포지토리를 설정하려면 다음 단계를 따르세요:

1. VisualSVN Server 다운로드 및 설치 – [VisualSVN Server](https://www.visualsvn.com/server/download/)를 사용하고 *.dump* 파일에서 기존 리포지토리를 가져오세요. 이렇게 하면 로컬에서 호스팅되는 SVN 리포지토리가 생성됩니다.

2. 리포지토리 접근 – [TortoiseSVN](https://tortoisesvn.net/)을 사용하여 리포지토리를 확인하세요. 이를 통해 리포지토리 내의 *.mpr* 파일이나 다른 파일을 검사할 수 있습니다.

    {{% alert color="info" %}}이전 리비전의 파일을 검사하려면 **TortoiseSVN**을 사용하고 **Update to revision**을 선택하여 특정 리비전을 확인하세요.{{% /alert %}}

#### 브랜치 내용 유지를 위한 해결 방법

이력 없이 마이그레이션하는 동안 메인 브랜치를 제외한 모든 브랜치가 제거됩니다. 모든 브랜치를 메인 브랜치에 병합하여 통합하는 것이 항상 가능하지 않으므로, 브랜치 내용을 수동으로 백업하고 마이그레이션 후 다시 생성할 수 있습니다.

{{% alert color="info" %}}
Mendix는 프로세스에 익숙해지기 위해 먼저 더미 프로젝트에서 이 단계를 시도할 것을 권장합니다.
{{% /alert %}}

다음 단계를 따르세요:

1. 유지하려는 각 브랜치에 대해:

    1. SVN 브랜치를 체크아웃합니다.
    2. 메인 브랜치의 최신 상태를 유지하려는 브랜치에 병합합니다. 이렇게 하면 공통 기반이 있어 마이그레이션 후 이 브랜치에서 충돌을 해결할 수 있습니다.
    3. *.svn* 폴더를 제외한 전체 프로젝트 폴더의 압축 .zip 버전을 생성합니다. 나중에 어떤 브랜치를 나타내는지 알 수 있도록 .zip 폴더의 이름을 명확하게 지정하세요.

2. 이력 없이 Git으로 마이그레이션합니다.
3. 유지하려는 브랜치를 다시 생성합니다. 메인 브랜치를 다른 Mendix 버전으로 업그레이드하기 전에 이 작업을 수행하세요. 각 브랜치에 대해:

    1. Studio Pro에서 메인 브랜치에서 새 브랜치를 생성하고 로컬에 클론합니다.
    2. *.git* 폴더를 제외한 프로젝트 폴더의 내용을 .zip의 내용으로 덮어씁니다.
    3. Studio Pro에서 *Branch recreated* 메시지로 변경 사항을 커밋하고 서버에 푸시합니다.

### 이력 포함 마이그레이션 {#with-history}

이력 포함 마이그레이션 동안 모든 브랜치의 리비전을 포함한 모든 앱 이력이 SVN에서 Git으로 복사됩니다.

리포지토리 크기에 따라 마이그레이션에 몇 시간이 걸릴 수 있습니다. 커밋 수가 많은 경우 Mendix는 개발자가 리포지토리에 접근할 필요가 없는 시간(예: 밤)에 이 작업을 수행할 것을 권장합니다.

{{% alert color="info" %}}

마이그레이션을 시작하기 전에 팀 멤버에게 변경 사항을 커밋하도록 알려주세요.

{{% /alert %}}

{{% alert color="warning" %}}

이전에 삭제된 SVN 브랜치는 마이그레이션 프로세스에 의해 Git 브랜치로 매핑되지 않으며 영구적으로 제거됩니다. 삭제된 SVN 브랜치가 사전에 다른 브랜치에 병합되지 않은 경우, 삭제된 SVN 브랜치에 속하는 커밋도 영구적으로 제거됩니다.

{{% /alert %}}

## 마이그레이션 후 단계

### 개발자를 위한 단계

마이그레이션 후 기존 로컬 복사본은 더 이상 작동하는 버전 제어 시스템에 연결되지 않습니다. 앱에서 작업하고 변경 사항을 버전 제어 시스템에 저장하려면 Team Server에서 앱을 체크아웃(다시 다운로드)해야 합니다. 다음을 수행하세요:

1. Studio Pro를 열고 Git으로 마이그레이션된 앱을 선택합니다. Git 아이콘으로 식별할 수 있습니다. Studio Pro에서 **Open**을 클릭하여 앱의 Git 버전을 다운로드합니다. 완료되면 변경 사항을 만들고 버전 제어에 저장할 수 있습니다.
2. 잘못된 앱 버전에서 작업하는 것을 방지하기 위해 앱의 이전 로컬 복사본을 제거합니다.

### 업그레이드 계획

급격한 리포지토리 성장 문제를 방지하기 위해 가능한 한 빨리 Studio Pro 버전 10.24 LTS로 업그레이드할 것을 강력히 권장합니다. 이렇게 하면 앱이 자동으로 [MPRv2](/refguide10/troubleshoot-repository-size/#mprv2)로 변환됩니다.

## 마이그레이션 실패 시

마이그레이션 프로세스가 실패하면 모든 변경 사항이 롤백됩니다. 이는 SVN에 대한 접근이 복원되고 앱 개발을 계속할 수 있음을 의미합니다.
아래에서 실패한 마이그레이션의 일반적인 원인을 확인하고 해결할 수 있습니다. 그 후 앱의 마이그레이션을 다시 시도할 수 있습니다.

마이그레이션이 실패한 가장 가능성 있는 이유는 Mendix 9.12 미만의 유효하지 않은 브랜치가 있다는 것입니다. 이를 해결하려면 이러한 브랜치를 삭제하거나 업그레이드하세요.
