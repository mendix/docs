## 소개

대소문자 구분 문자열 연산은 대문자와 소문자를 다른 문자로 간주하는 연산입니다.
쿼리에서 문자열에 영향을 미치는 연산(예: XPath 제약 조건 내부)은 Mendix 애플리케이션에서 사용하는 데이터베이스 공급업체, 버전 및 구성에 따라 대소문자를 구분하거나 구분하지 않을 수 있습니다.

또한 대소문자 비구분 연산의 각 구현은 문자의 대소문자 정규화를 다르게 처리할 수 있다는 점에 유의하는 것이 중요합니다.
일반적인 규칙으로, 정규화는 로케일을 기반으로 합니다. 이것은 데이터베이스/테이블에서 명시적으로 지정되거나 데이터베이스가 운영 체제에서 추론합니다.
이 문자 정규화 또는 케이스 폴딩은 *World Wide Web Consortium* 위키의 [Case Folding](https://www.w3.org/International/wiki/Case_folding)에서 더 자세히 설명되어 있습니다.

이 문서의 목적을 위해 대소문자 구분 연산을 세 가지 범주로 나눌 수 있습니다:

* 정렬: 객체를 검색하려는 순서(알파벳 오름차순 또는 내림차순)를 나타냅니다.
* 비교: 쿼리에서 직접 같음 또는 기타 비교를 포함하는 연산입니다(예: 쿼리 `\\Entity[Attribute = 'a']`에서)
* 문자열 함수: XPath의 [contains](/refguide8/xpath-contains/), [starts-with](/refguide8/xpath-starts-with/), [ends-with](/refguide8/xpath-ends-with/) 함수입니다.

아래에 달리 명시되지 않는 한, 문자열 정렬 및 비교는 대소문자를 구분하며 문자열 함수는 대소문자를 구분하지 않습니다.
이것은 데이터베이스, 테이블 또는 열 데이터 정렬의 영향을 받으며, 때로는 다른 데이터베이스 특정 옵션에 의해 영향을 받습니다.
사용 가능한 데이터 정렬 및 옵션은 공급업체(및 때로는 버전)에 따라 다릅니다.

## 데이터베이스 유형별 대소문자 구분 동작

다음 섹션에서는 Mendix에서 지원하는 데이터베이스의 기본 동작을 설명합니다.

### HSQLDB

정렬, 비교, 문자열 함수에 대해 **대소문자를 구분하지 않습니다**.

### POSTGRESQL

정렬 및 비교는 **대소문자를 구분합니다**. 구성할 수 없습니다.

문자열 함수는 `ILIKE` SQL 연산자를 사용하여 구현되므로 **대소문자를 구분하지 않습니다**.

### DB2

버전 [8.14.0](/releasenotes/studio-pro/8.14/) 이상부터 정렬 및 비교는 **대소문자를 구분합니다**. 8.14 미만 버전에서는 모든 연산이 **대소문자를 구분합니다**. 두 버전 그룹 모두 데이터 정렬이 **대소문자를 구분하지 않도록** 구성된 경우 예외가 있으며, 이는 모든 연산에 영향을 미칩니다. 자세한 내용은 *DB2*의 [DB2 대소문자 구분 없이 만들기](/refguide8/db2/#making) 섹션을 참조하십시오.

무제한 길이의 문자열 Attribute에 대한 정렬을 지원하지 않습니다.

### MARIADB, MYSQL

모든 연산은 구성된 데이터 정렬에 따라 다릅니다.
`utf8` 문자 세트를 사용할 때 기본 데이터 정렬은 `utf8_general_ci`이고, `latin1` 문자 세트를 사용할 때는 `latin1_swedish_ci`입니다.
이러한 기본 데이터 정렬은 모두 **대소문자를 구분하지 않습니다**.

### ORACLE

정렬 및 비교는 구성된 데이터 정렬에 따라 다릅니다.
기본 데이터 정렬은 `binary`이며, 이는 **대소문자를 구분**하지만, 대소문자를 구분하지 않는 연산을 위해 `binary_ci`를 사용할 수 있습니다.

`NLS_SORT` 및 `NLS_COMP` "Linguistic Sort Parameters"에 다른 값을 설정하여 정렬 및 비교 연산에 대해 다른 데이터 정렬을 설정할 수 있습니다.

무제한 길이의 문자열 Attribute에 대한 비교를 지원하지 않습니다.

문자열 함수는 데이터베이스의 `UPPER` 함수를 사용하여 모든 문자를 대문자로 변환하여 구현되므로 **대소문자를 구분하지 않으며** 실행되는 `locale`에 민감하지 않습니다.

### SAP HANA

무제한 길이의 문자열 Attribute에 대한 정렬 또는 비교를 지원하지 않습니다.

### SQL SERVER

모든 연산은 데이터 정렬에 따라 다릅니다.
기본 권장 데이터 정렬은 `SQL_Latin1_General_CP1_CI_AS`입니다.
자세한 내용은 [새 SQL Server 데이터베이스 설정](/developerportal/deploy/setting-up-a-new-sql-server-database/) 가이드와 Microsoft 문서 [Windows Collation Name](https://docs.microsoft.com/en-us/sql/t-sql/statements/windows-collation-name-transact-sql)을 참조하십시오.

## 기본 대소문자 구분 개요

이 테이블은 다양한 데이터베이스 유형별 기본 대소문자 구분을 나타냅니다:

| **데이터베이스 유형** | **비교** | **정렬** | **문자열 함수** |
|------------------:|:--------------:|:-----------:|:--------------------:|
| HSQLDB            | I              | I           | I                    |
| POSTGRESQL        | S              | S           | I                    |
| DB2               | S              | S¹          | I³                    |
| MARIADB, MYSQL   | C              | C           | C                    |
| ORACLE            | C¹             | C           | I                    |
| SAP HANA          | S¹             | S¹          | I²                    |
| SQL SERVER        | C              | C           | C                    |

문자의 의미는 다음과 같습니다:

* **S** – 대소문자 구분
* **C** – 데이터 정렬/구성에 따라 다름
* **I** – 대소문자 구분 없음

¹무제한 길이의 문자열에서는 연산이 지원되지 않습니다.
²Mendix 8.11.0부터
³Mendix 8.14.0부터
