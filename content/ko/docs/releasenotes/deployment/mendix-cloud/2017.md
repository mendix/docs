## December 2017

### December 29, 2017

#### Fixes

* Mendix Cloud v4에서 **archived log** 기능이 사용자가 선택한 것보다 더 넓은 시간 범위의 로그를 반환했습니다(예: 1일 로그가 2일간의 로그 데이터를 반환). 이 문제가 수정되었습니다.

### December 22, 2017

#### Improvements

* Mendix Cloud 환경에 **Restart** 버튼을 도입합니다. 이 기능은 구성 변경을 준비하고 한 번의 클릭으로 활성화하는 데 유용합니다.

#### Fixes

* Cloud v4에서 Mendix 6 애플리케이션을 스케일링할 수 있게 되었습니다. 이전에는 Mendix 7 앱을 실행하는 환경에서만 가능했습니다. Mendix 6 앱에서는 할당된 메모리만 스케일링할 수 있으며, 인스턴스 수는 스케일링할 수 없습니다.
* v4 환경에서 대용량 백업을 지원합니다. 5GB보다 큰 백업 패키지를 업로드하지 못하던 문제를 수정했습니다.
* 일부 Mendix Cloud v3 사용자가 환경에 대한 특정 Java 버전을 설정할 수 없었던 문제를 수정했습니다.
* Mendix Cloud 환경 상태 아이콘 위에 마우스를 올리면 환경 상태에 대한 더 많은 정보가 표시됩니다.

### December 13, 2017

#### Fixes

* Cloud v4의 JVM Process Memory 그래프에 이제 애플리케이션의 네이티브 메모리도 표시됩니다.
* Cloud v4의 Application Node Operating System Memory 그래프가 이제 total과 used 두 개의 라인으로 표시됩니다. 이전 버전은 total을 used에 더하여 누적 영역 그래프로 표시했는데, 이는 매우 혼란스러웠습니다.

### December 6, 2017

#### Fixes

* Free App이 iframe에 삽입되는 것을 방지하는 문제를 해결했습니다.

## November 2017

### November 27, 2017

#### Improvements

* Free App 사용자는 이제 애플리케이션 모델을 편집하기 위해 Web Modeler와 Desktop Modeler 중에서 선택할 수 있습니다.

### November 15, 2017

#### Improvements

* Mendix Cloud v4 백업을 이제 동일한 Mendix Cloud 노드의 다른 환경으로 복원할 수 있습니다. 이 기능은 프로덕션 마이그레이션을 준비하거나 오류를 재현하는 데 유용합니다.
* Team Server에서 배포 패키지를 생성할 때, 대화 상자에서 대소문자 구분 없는 순서로 브랜치를 표시하여 사용자에게 더 적합한 방식으로 제공합니다.
* Mendix Cloud v4 알림 상태가 오류로 인해 가끔 `UNKNOWN`을 표시했습니다. 이 문제가 수정되어 올바른 상태가 표시됩니다.
* **Deploy**, **Operate**, **Backups** 페이지에서 드디어 <kbd>Enter</kbd> 키를 사용하여 2단계 인증 코드를 제출할 수 있습니다. 즐거운 타이핑 되세요!

## October 2017

### October 20, 2017

#### Improvements

* 실행 중인 애플리케이션을 중지하지 않고 다른 버전을 배포하는 기능이 Mendix Cloud v3에서도 사용 가능합니다. 배포가 완료되면 한 번의 클릭으로 애플리케이션을 다시 시작할 수 있습니다.
* Mendix Cloud v4에서 백업 업로드 사용자 경험이 개선되었습니다. 또한 Mendix Cloud v4에서 이전 백업을 수동으로 삭제하는 것도 가능합니다.
* Mendix Cloud v4의 메트릭에 대한 일련의 사소한 사용자 경험 개선 사항을 적용했습니다.

#### Fixes

* Team Server에서 배포 패키지를 생성할 때, 사용자는 이제 Mendix Modeler 없이 커밋된 리비전을 볼 수 있습니다.

### October 10, 2017

#### Improvements

* 활동 로그를 정리하고 사용자에게 유용한 정보를 제공하지 않는 것으로 판단되어, Mendix Cloud의 모든 애플리케이션에서 백업 만료 항목을 활동 로그에서 제거했습니다.

## September 2017

### September 28, 2017

#### Improvements

* 거의 다운타임 없는 배포: 이제 실행 중인 애플리케이션을 중지하지 않고 다른 버전을 배포할 수 있습니다. 배포가 완료되면 한 번의 클릭으로 애플리케이션을 다시 시작할 수 있습니다. 이 기능은 현재 Mendix Cloud v4에서 사용 가능합니다. Mendix Cloud v3에서는 곧 사용 가능할 예정입니다.
* Deploy API의 견고성을 개선했습니다: Deploy API를 통해 환경을 시작/중지할 때 가끔 발생하던 오류가 더 이상 발생하지 않습니다.
* Mendix Cloud v4에서 아시아 태평양 사용자를 위한 배포 패키지 전송 안정성을 개선했습니다.
* 환경 상태 지표가 이제 훨씬 더 정확합니다.

## August 2017

### August 30, 2017

#### Improvements

* Cloud v4의 인스턴스/메모리 슬라이더의 사용자 인터페이스가 상당히 개선되었습니다. 스케일링은 애플리케이션의 활동 로그에도 표시됩니다.
* Mendix Cloud v4의 경우 아카이브 로그의 크기를 더 이상 표시하지 않습니다. 이전에 표시된 크기가 잘못되었습니다.
* Mendix Cloud 백업의 만료 날짜가 이제 백업 목록에서 표시됩니다.

### August 22, 2017

#### Improvements

* 다양한 최적화로 인해 Mendix Cloud v4 EU에서 앱의 배포 속도가 이제 약 두 배 빨라졌습니다. 모든 Mendix Cloud v4 리전에서 FileDocument 읽기/쓰기 작업의 지연 시간도 개선되었습니다.

### August 15, 2017

#### Improvements

* 모든 Mendix Cloud v3 앱에서 경로 기반 접근 제한을 활성화했습니다. 이를 통해 사용자는 환경에 대한 접근 제한을 더 쉽게 구성할 수 있습니다. 자세한 내용은 [Access Restrictions](/developerportal/deploy/access-restrictions/)를 참조하세요. Mendix Cloud v4에는 이미 이 기능이 활성화되어 있습니다.

### August 1, 2017

#### Improvements

* Mendix Cloud v3의 경우 가장 최근 보안 업데이트를 포함한 Java 업그레이드가 진행됩니다. Java KeyStore도 업데이트되었습니다. 이 키스토어는 Mendix 앱에서 나가는 보안 연결을 위한 신뢰할 수 있는 루트 인증서를 포함합니다. 예를 들어, 업데이트된 Java KeyStore를 사용하면 [Let's Encrypt](https://letsencrypt.org/)가 서명한 인증서를 사용하는 엔드포인트에 연결할 수 있습니다. Oracle과 Mozilla가 안전하지 않다고 판단한 루트 인증서는 제거되었습니다. 앱을 다시 시작하면 자동으로 최신 Java 버전과 KeyStore를 사용하게 됩니다. Mendix Cloud v4의 경우 이 수정 사항의 배포를 아직 계획 중입니다.

## July 2017

### July 31, 2017

#### Fixes

* Mendix Cloud v4의 앱에 대한 [Deploy API](/apidocs-mxsdk/apidocs/deploy-api/)에 시작, 중지 및 전송 호출에 여러 버그가 포함되어 있었습니다. 이제 수정되었습니다.

### July 18, 2017

#### Improvements

* Mendix Cloud에서 실행되는 모든 앱에 대해 다음 HTTP 요청 헤더를 사용할 수 있습니다: `SSL-Protocol`(가능한 값: `TLSv1`, `TLSv1.1`, `TLSv1.2`) 및 `SSL-Cipher`(예: `ECDHE-RSA-AES256-GCM-SHA384`). 이를 사용하여 로그인 시도를 차단할 수 있습니다(예: `TLSv1` 연결). *(이전 릴리스 노트에서 헤더 이름이 `SSL-Version`이라고 명시했으나, 올바른 이름은 `SSL-Protocol`입니다.)*
* 최신 브라우저는 정적 HTML 리소스를 적극적으로 캐시하는데, 이로 인해 새 버전의 애플리케이션 배포 후 사용자 문제가 발생할 수 있습니다. 캐시를 지우면 이 문제를 해결할 수 있지만 이는 좋지 않은 사용자 경험입니다. 따라서 Mendix Cloud v3에서 실행되는 모든 앱에 대해 리소스 `/` 및 `/index.html`, `/login.html`, `/index[0-9].html`에 명시적인 `no-cache` 헤더를 추가했습니다. Mendix Cloud v4의 경우 음수 값의 `expires`가 이미 사용되고 있어 변경이 필요하지 않습니다. 이 변경으로 지금까지 발생했던 대부분의 브라우저 캐싱 문제가 해결될 것으로 판단됩니다.
* 이제 IP 범위를 기반으로 Mendix Cloud v4 애플리케이션에 대한 접근을 제한할 수 있습니다. 이 기능은 모든 Mendix Cloud v4 리전에서 사용 가능하며 클라우드 환경의 **Connectivity** 탭에서 구성할 수 있습니다.

#### Fixes

* Mendix Cloud에서 관리자 사용자 비밀번호를 업데이트할 때 비밀번호 정책 설명이 잘못되어 혼란스러운 상황이 발생했습니다. 텍스트를 업데이트했습니다.
* **Node Security**로 이동할 때 **App Team** 탭이 더 이상 사라지지 않습니다.
* Mendix 7.5.0의 ZIP 파일 인코딩 변경으로 인해 Mendix Cloud에 배포할 때 AppServices를 파싱할 수 없었습니다. 이 문제를 수정했습니다.
* **View Current Log** 버튼이 Free App에서 더 이상 숨겨지지 않습니다.

## May 2017

### May 19, 2017

#### Fixes

* Mendix Cloud v4의 유료 애플리케이션에 대한 백업 보관 체계를 수정하여, 이제 Mendix Cloud v3과 동일합니다.
* Mendix Cloud v4 애플리케이션의 "view current log" 기능이 기본적으로 비어 있었으며 **Show all** 버튼을 사용해야 했습니다. 이제 콘텐츠가 즉시 표시됩니다.

### May 17, 2017

#### Improvements

* Mendix Cloud v4에서 앱으로의 연결에 사용되는 SSL/TLS 암호를 업그레이드했습니다. 이에는 블록 기반 암호(3DES) 제거 및 2048비트 DH 매개변수로의 전환이 포함됩니다. Mendix Cloud v4는 이제 [SSL Labs에서 A+ 등급](https://www.ssllabs.com/ssltest/index.html)을 받았습니다.
* Mendix Cloud v3 및 Mendix Cloud v4의 모든 앱에 대한 HTTP/2 연결 지원을 추가했습니다. HTTP/2는 모든 주요 브라우저에서 지원되며 보다 효율적인 네트워크 연결을 제공합니다. [HTTP/2에 대한 자세한 내용은 여기를 참조하세요](https://http2.github.io/faq/).

### May 4, 2017

#### Improvements

* 새 배포 패키지를 전송하면 "Deploy successful" 화면에서 끝나는 문제가 있었습니다. 이제 훨씬 더 유용한 환경 세부 정보 화면으로 리다이렉트됩니다.

#### Fixes

* Mendix Cloud v4에서 대용량 백업 실패 문제를 수정했습니다. 이제 백업은 데이터베이스의 디스크가 가득 찬 경우에만 실패합니다.
* Alert Details에서 올바른 메뉴 항목이 하이라이트됩니다.
* 동시에 생성된 두 앱이 동일한 도메인 이름을 받을 수 있는 경쟁 상태를 수정했습니다.
* 사용자가 환경을 지우는 것을 방지하기 위해 백업 복원 전 경고 메시지를 추가했습니다. 복원 전 환경을 지우면 훨씬 느린 비증분 복원 작업이 발생했습니다.
* Mendix Cloud v4 Pro/Enterprise 환경에서 빈 환경으로의 "Data Snapshots" 자동 복사를 비활성화했습니다. 이 기능은 Free App에서만 사용됩니다. 데이터베이스 스냅샷의 약한 관리자 비밀번호가 앱 시작을 방지했습니다.

## April 2017

### April 1, 2017

#### Improvements

* [Deploy API](/apidocs-mxsdk/apidocs/deploy-api/)에 백업 목록 조회/백업 다운로드 작업을 추가했습니다.
* Deploy/Operate 탭에서 **Security** 링크를 업데이트했습니다. 이제 플랫폼의 모든 페이지에서 동일한 페이지로 이동합니다.

#### Fixes

* 알림 이메일의 상태 페이지 링크를 수정했습니다.
* 일부 경우에 Free App 백업 페이지가 매우 느리거나 오류가 발생하던 문제를 수정했습니다.
* Free App의 로그 뷰어가 HTML을 이스케이프하지 않아, 애플리케이션이 일반 HTML을 기록하면 브라우저에서 해석되던 문제를 수정했습니다.
* 동일한 환경에서 두 개의 다른 환경으로 동시 스냅샷 복원 작업이 하나의 환경을 잠글 수 있던 문제를 수정했습니다.

## March 2017

### March 20, 2017

#### Fixes

* 이전 릴리스에서 도입된 위젯 비호환성으로 인해 Platform Portal의 Deploy / Operate 섹션이 Internet Explorer 11에서 작동하지 않았습니다. 이 문제는 3월 16일에 프로덕션에서 긴급 패치되었습니다.

### March 13, 2017

#### Fixes

* **Operate -> Backups**를 클릭하면 Free App에서 오류가 발생했습니다. 이 문제가 수정되었습니다.

### March 10, 2017

#### Improvements

* **Node Security**에 새로운 설정을 도입했습니다. 이제 **Monitoring Permissions**를 **Transport Permissions**와 별도로 구성할 수 있습니다. 이 변경 직후, 환경에 대해 **Transport Permissions**를 가진 모든 사용자에게 **Monitoring Permissions**도 부여했습니다. 이후부터 **Technical Contact**가 팀의 각 구성원에 대해 이러한 설정을 별도로 구성할 수 있습니다. 이 설정을 도입하면서 **Node Security** 화면의 레이아웃을 재검토하여, 각 환경에 대한 권한을 변경할 수 있는 더 간단한 인터페이스를 제공합니다.

## February 2017

### February 20, 2017

#### Improvements

* Mendix Cloud v3의 로그 라인에서 정적 정보를 제거했습니다. 이전에는 모든 라인에 `tr10000`과 `127.0.0.1`이 포함되어 있었습니다. 이 필드들은 쓸모없었기 때문에 제거했습니다.
