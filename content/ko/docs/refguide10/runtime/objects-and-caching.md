## 소개

이 페이지에서는 객체가 데이터베이스에서 로드되는 방법, 어떤 경우에 객체가 캐시되는지, 캐시된 객체가 검색되는 시기, 객체가 변경되고 커밋될 때 어떤 일이 발생하는지에 대해 설명합니다.

"객체"라는 용어는 Mendix Entity의 인스턴스를 의미합니다.

## 객체 캐싱

Mendix는 여러 요청에 걸쳐 Mendix Runtime 내에서 객체를 캐시하지 않습니다. 하지만 요청 내에서 변경된 객체에 대한 참조를 수집하고 유지합니다. 일부 검색 액션에서는 이 객체가 데이터베이스보다 우선되고, 다른 액션에서는 그렇지 않습니다. 이는 성능과 시스템 작동 방식에 영향을 미칩니다.

## 추적되는 객체

Non-persistable 객체, 새 객체, 변경된 객체만 추적됩니다. 이는 런타임에서 요청 기간 동안 메모리에 보관됨을 의미합니다. 요청이 완료되면 객체 상태가 클라이언트에 반환되거나, 클라이언트가 아닌 액션의 경우 폐기됩니다. 객체가 커밋되면 Non-persistable 객체를 제외하고 더 이상 추적되지 않습니다. 객체의 롤백에도 동일하게 적용됩니다.

변경되지 않은 기존 객체는 요청 범위에서 추적되지 않습니다. 변경될 때만 추적됩니다!

{{% alert color="warning" %}}
Mendix Runtime은 클라이언트가 해당 상태에 접근할 수 있는 충분한 권한이 없는 경우 클라이언트에 객체 상태를 반환할 수 없습니다. 이는 읽기 권한이 없는 객체를 변경하지만 커밋하지 않는 Microflow를 트리거하면, 요청이 끝날 때 변경 사항이 폐기됨을 의미합니다.
{{% /alert %}}

## 추적 범위 {#scope-tracking}

객체는 요청 범위에서 추적됩니다. 요청 범위는 항상 세션 범위보다 작으며 컨텍스트 간에 공유될 수 있습니다. API `ISession.createContext()`를 사용하면 새 컨텍스트와 함께 새 요청 범위가 생성됩니다. 컨텍스트가 복제되면 요청 범위가 복제된 컨텍스트와 공유됩니다. 요청 범위에 대한 변경 사항은 복제된 모든 컨텍스트에서 볼 수 있습니다.

## 액션

### 추적된 객체를 반환하는 액션

일부 액션은 먼저 요청 범위에서 객체를 읽습니다. 사용할 수 없는 경우 데이터베이스에서 읽습니다. 이러한 액션은 다음과 같습니다:

* 경로별 검색/연관 검색 (`Core.retrieveByPath([..])`)
* ID별 검색/ID 목록별 검색 (`Core.retrieveId([..])` 및 `Core.retrieveIdList([..])`)

이는 검색할 객체가 요청 범위에서 추적되는 경우(변경되었거나, 새 객체이거나, Non-persistable인 경우) 이러한 액션/API를 호출하면 요청 범위에서 객체를 반환함을 의미합니다.

### 추적된 객체를 반환하지 않는 액션

하나의 액션은 항상 요청 범위를 무시하고 항상 데이터베이스에서 객체를 읽습니다: XPath 검색(모든 변형).

이는 객체가 변경되어 요청 범위에서 추적되고 있더라도 데이터베이스에서 객체의 새 복사본을 읽습니다. 동일한 Entity 인스턴스의 복사본 중 하나에 대한 변경은 다른 복사본에서는 보이지 않습니다!

## 영향

### 솔루션에 대한 이 동작의 영향

Entity 인스턴스에 대한 여러 참조가 있고 이러한 참조를 다른 방법으로 가져온 경우, 동일한 Entity 인스턴스의 복사본일 수 있습니다. 복사본 중 하나에 대한 변경 사항이 다른 복사본에 반영되지 않을 수 있음을 유의하십시오.

이를 식별하는 명확한 방법이 없으므로, 최신 버전의 객체를 확보하기 위해 데이터베이스에 변경 사항을 커밋한 직후 객체를 다시 읽어야 합니다.

### Microflow에 대한 영향

이 동작은 유사한 방식으로 Microflow에 영향을 미칩니다. 따라서 여기서 모범 사례는 (잠재적으로) 동일한 객체의 다른 참조에 변경 사항을 커밋한 직후 객체를 다시 로드하는 것입니다.

### Microflow 및 Java Action에서 Non-Persistable Entity 및 변경된 Entity 사용의 영향

사용자가 클라이언트에서 Microflow를 호출하면 상태의 복사본이 런타임에 대한 요청과 함께 전송됩니다. 이 복사본은 런타임에 유지되며 이 요청의 처리 중에 런타임에 의해 업데이트됩니다. 요청 처리가 완료된 후 클라이언트에 반환되며, 클라이언트는 응답에서 반환된 정보로 클라이언트 상태를 업데이트합니다.

서버 측에서 이 상태는 해당 요청 처리 액션에서만 접근할 수 있습니다. 이는 다른 요청에 의해 업데이트되는 경우 Non-persistable Entity의 상태를 쿼리하는 것이 더 이상 불가능하다는 것을 의미합니다. 클라이언트를 통해서만 가능합니다(다른 요청이 이 Non-persistable Entity를 클라이언트에 반환해야 하고, 클라이언트가 이를 서버에 대한 후속 요청과 함께 전송해야 하기 때문입니다).

요청이 런타임에서 비동기 액션을 트리거하면 시작된 시점의 상태를 가져옵니다. 비동기 액션이 클라이언트에 의해 비동기적으로 실행된 경우에만 클라이언트에서 액션을 추적하고 비동기 액션이 완료되면 업데이트된 상태를 가져올 수 있습니다. Java Action을 사용하여 런타임에서 비동기 액션이 트리거되면 상태 업데이트를 클라이언트에서 추적할 수 없습니다(새로 고침, 데이터 유효성 검사 및 기타 명령과 유사).
