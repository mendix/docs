## December 2021

### December 23, 2021

#### Improvements

* 앱 팀 구성원 변경 및 팀 구성원의 [권한](/developerportal/deploy/node-permissions/) 변경을 기록하는 활동 로그 항목을 추가했습니다.
* 환경 세부 정보의 [Model Options 탭](/developerportal/deploy/environments-details/#model-options)에서 [예약된 이벤트](/refguide9/scheduled-events-legacy/#common-properties)와 관련된 문서를 표시합니다.

#### Fixes

* 백업 파일 업로드가 멈추고 완료되지 못하던 문제를 수정했습니다. (Tickets 134454, 134887, 134898, 135007, 135325, 135359, 135692, 135894, and 137806)

### December 22, 2021

#### Improvements

New Certificate Details: [https://crt.sh/?id=5832398831](https://crt.sh/?id=5832398831)

## October 2021

### October 26, 2021

#### Improvements

Mendix Cloud v4에서 이제 PostgreSQL 13을 지원합니다. 이는 일부 워크로드에 대해 상당한 성능 향상을 제공합니다.

새로 생성된 모든 애플리케이션은 PostgreSQL 13이 실행되는 데이터베이스를 갖게 됩니다.

기존 애플리케이션은 향후 몇 주 내에 업데이트됩니다. 이러한 애플리케이션의 Technical Contact는 적시에 알림을 받으며, 추가로 유지보수 정보가 Developer Portal에 표시됩니다.

### October 7, 2021

#### Fixes

* 사용자가 모든 백업을 볼 수 없고 일부 백업이 두 번 이상 표시되던 문제를 수정했습니다. (Tickets 127908, 128966, 130090, and 130313)

## July 2021

### July 23, 2021

#### Improvements

* 서비스 브로커에서 제공하는 정보를 사용하여 PostgreSQL 버전을 동적으로 만들어 환경 세부 정보를 개선했습니다. 버전은 환경 재시작 후 업데이트됩니다.

#### Fixes

* REST 엔드포인트에 대해 사용자 정의 JSON 오류 설명이 반환되지 않던 문제를 수정했습니다. 앱에 대해 사용자 정의 HTML 오류 페이지를 정의한 경우, 일반적으로 HTML 콘텐츠를 제공하지 않는 요청 핸들러에 대해서는 비활성화됩니다. 여기에는 앱에서 정의한 SOAP, OData 및 REST 엔드포인트가 포함됩니다.
* 무료 애플리케이션 환경 페이지에서 Mendix Cloud에 배포되지 않은 앱이 배포된 것으로 표시되던 문제를 수정했습니다.

### July 15, 2021

#### Improvements

* Mendix Cloud v4에서 이제 Internet Protocol version 6(IPv6)을 통한 수신 연결을 지원합니다.

### July 5, 2021

#### Fixes

* [Backups API v1](/apidocs-mxsdk/apidocs/backups-api-v1/) 사용 시 장시간 실행되는 복원 작업이 실패한 것으로 나타나는 문제를 수정했습니다. (Tickets 122197 and 125707)

#### Announcement

* [Backups API 버전 1](/apidocs-mxsdk/apidocs/backups-api-v1/)을 더 이상 사용하지 않습니다. Mendix는 장시간 실행되는 백업 및 복원 작업을 더 안정적으로 처리하는 [Backups API v2](/apidocs-mxsdk/apidocs/backups-api/)를 사용하는 것을 권장합니다.

## May 2021

### May 27, 2021

#### Improvements

* Mendix Cloud v4에서 일일 백업이 이제 30일간 보관됩니다. 이전에는 2주였습니다.

### May 18, 2021

#### Improvements

* Mendix Cloud 도메인 `mendixcloud.com` 및 `mxapps.io`가 이제 DNSSEC를 사용하여 DNS 조회를 인증합니다. 이 변경이 적용되기 위해 별도의 조치가 필요하지 않습니다. 앞으로 이 도메인에 대한 모든 DNS 요청은 자동으로 DNSSEC를 사용합니다.

### May 12, 2021

#### Improvements

* Mendix Cloud 데이터베이스 백업이 이제 `pg_dump` 버전 1.14로 생성됩니다. 이 버전은 2019년 10월부터 PostgreSQL과 함께 배포됩니다(PostgreSQL 12, 13). 부작용으로 1.14 미만의 `pg_restore` 버전(PostgreSQL <= 11)으로는 이러한 PostgreSQL 백업을 복원할 수 없습니다. 발생하는 오류는 `pg_restore: [archiver] unsupported version (1.14) in file header`입니다. 이 문제를 해결하려면 최신 버전의 `pg_dump` 및 `pg_restore`가 포함된 소프트웨어로 업그레이드하세요. 예시로 PostgreSQL 클라이언트 버전 12 또는 13, [PGAdmin 버전 4.12 이상](https://www.pgadmin.org/download/)이 있습니다.

## April 2021

### April 29, 2021

#### Improvements

* 앱을 [스케일링](/developerportal/deploy/environments-details/#scaling)할 때 설정할 수 있는 최대 인스턴스 수를 32개로 늘렸습니다. 32개 이상의 인스턴스가 필요하면 Mendix Support에 문의하세요.

#### Announcement - **2021년 7월 1일**부터 Mendix Cloud v4의 애플리케이션에서 Internet Protocol Version 6(IPv6) 지원

Mendix Cloud v4 애플리케이션에 대한 연결의 보안과 확장성을 향상시키기 위해, **2021년 7월 1일**에 **Mendix Cloud v4**에서 **Internet Protocol Version 6(IPv6)** 지원을 활성화합니다. 이 작업은 자동으로 수행되며 앱을 다시 배포할 필요가 없습니다.

IPv6 지원을 활성화하면 Access Restriction Profiles가 구성된 Mendix 애플리케이션에 접근하는 클라이언트가 IPv6를 사용할 때 연결하지 못할 수 있습니다.

**이것이 의미하는 바**

Access Restriction Profiles를 업데이트하고 사용자에게 이 변경에 대해 알릴 수 있도록 이 날짜에 대해 알려드립니다. 영향을 받는 앱의 Technical Contact에게도 직접 연락할 예정입니다.

7월 1일 이전에 IPv6 범위를 구성할 수 있지만, 변경 사항은 해당 날짜에만 적용됩니다. IP 범위 설정 방법은 [Access Restriction Profiles](/developerportal/deploy/access-restrictions/#ip-ranges) 문서에서 확인할 수 있습니다.

**클라이언트 테스트**

클라이언트(브라우저 또는 통합 클라이언트)가 IPv6를 사용하는지 [https://ipv6-test.com](https://ipv6-test.com/)을 사용하여 테스트할 수 있습니다.

**영향**

Access Restriction Profiles가 구성된 애플리케이션에 연결하기 위해 IPv6를 사용하는 모든 클라이언트는 **2021년 7월 1일** 이후 연결 문제가 발생할 수 있습니다.

### March 16, 2021

* Mendix Cloud에 배포된 앱에 대한 사용 정보를 Mendix에 다시 전송하도록 Mendix 런타임을 업데이트했습니다. 이 변경에 대한 자세한 내용은 아래를 참조하세요.

    이 기능은 다음에 앱을 다시 배포할 때 활성화됩니다. 

**이 정보는 어떻게 처리됩니까?**

이 정보를 조회하는 유일한 목적은 라이선스 구독에 대한 준수 여부를 확인하는 것입니다. Mendix에 전송된 정보를 통해 앱의 정확한 사용량과 특정 기간의 활성 사용자 수에 대한 명확한 인사이트를 제공할 수 있습니다. 이는 장기적으로 최적의 사용자 플랜을 결정하는 데도 도움이 됩니다.

이 정보는 최종적으로 Mendix 내에 저장되며 앱 사용에 대한 집계 뷰를 제공합니다. 

**어떤 정보가 전송됩니까?**

이 맥락에서 사용 정보는 사용자 이름, 프로젝트 ID, 앱 환경 이름, 로그온 날짜 및 시간입니다. 
**사용자 이름은 해싱 알고리즘을 사용하여 스크램블링**되어 실제 사용자 이름을 알 수 없습니다. 

**사용자란 누구입니까?**

사용자 이름과 비밀번호로 앱에 로그인하는 모든 사람이 앱 사용자로 간주됩니다. 모든 익명 사용자는 이 목적상 단일 사용자로 취급됩니다.

**언제 어떻게 이루어집니까?**

연결된 환경에서 이 사용 정보는 정기적으로 자동으로 Mendix에 전송됩니다 — 기본적으로 하루에 한 번으로 설정됩니다. 이 전송은 자정 무렵(무작위)에 이루어집니다. 앱이 재시작될 때도 데이터가 전송됩니다. 

### March 3, 2021

* [deploy API](/apidocs-mxsdk/apidocs/deploy-api/), [Build API](/apidocs-mxsdk/apidocs/build-api/), Team Server API, [Backups API v2](/apidocs-mxsdk/apidocs/backups-api/), [Backups API v1](/apidocs-mxsdk/apidocs/backups-api-v1/)을 다음과 같이 업데이트했습니다:
    * JSON 유효성 검사 추가
    * 더 엄격한 API 경로 유효성 검사 추가(예: API 경로에 후행 `/`가 있으면 `API not found` 반환)
    * 처리되지 않거나 예기치 않은 오류에 대해 다르게 형식화된 오류 메시지 반환
    * Deploy API의 [Upload Package](/apidocs-mxsdk/apidocs/deploy-api/#upload-package) 호출에서 패키지 이름은 쿼리의 일부여야 합니다 — 더 이상 요청 본문에서 전달할 수 없습니다

API 사용 시 오류가 발생하면, Mendix Support에 문의하기 전에 형식이 문서와 정확히 일치하는지 확인하세요. 추가 또는 수정된 헤더 또는 요청 본문이 API 실패를 유발할 수 있습니다.

## February 2021

### February 22, 2021

* Datadog와의 통합을 지원하는 기술에 대한 주요 개선 사항을 릴리스했습니다. 이에 다음 기능이 추가됩니다:
    * 프로그램 흐름 추적(Datadog의 설정 방법은 https://docs.datadoghq.com/tracing/setup_overview/setup/java 참조)
    * Datadog 로그에서 이메일 주소 수정

    이러한 변경 사항을 구현하려면 앱을 다시 배포해야 합니다. 기존의 모든 메트릭은 계속 Datadog에 전송됩니다. 데이터베이스 비율 및 카운터 메트릭에 대한 약간의 변경 사항이 있지만, 게이지에는 영향을 미치지 않습니다. 자세한 내용은 [Datadog for v4 Mendix Cloud](/developerportal/operate/datadog-metrics/)를 참조하세요.
