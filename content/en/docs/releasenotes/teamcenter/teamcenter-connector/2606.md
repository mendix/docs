## 2606.1.0

**Release date:** November 19, 2026

{{% button color="info" href="https://marketplace.mendix.com/link/component/111627" text="Go to Marketplace" title="Download the Teamcenter Connector from the Marketplace" %}}

**Requirements:** Studio Pro 11.12.4 or above

**Security Issues Fixed:** [CVE-2026-89425](https://www.cve.org/CVERecord?id=CVE-2026-89425), [CVE-2026-89407](https://www.cve.org/CVERecord?id=CVE-2026-89407), [CVE-2026-91777](https://www.cve.org/CVERecord?id=CVE-2026-91777), [CVE-2026-91776](https://www.cve.org/CVERecord?id=CVE-2026-91776)

### New Features

#### Connector

* **Teamcenter Context for Maia** – The Teamcenter Connector now has Mendix AI Assistance (Maia) skills that help you create Teamcenter integrations in Mendix. The skills provide general information on Mendix Teamcenter integrations, Teamcenter domain knowledge, the Teamcenter Connector and Service document, and the concept of business object mappings. In addition, we added a dedicated skill to help developers set up their Teamcenter instances in the connector and Service document.
* **Teamcenter Workflow** – The Teamcenter Connector now has implementation microflows that make it much easier to integrate with Teamcenter workflow. The toolbox has a new category called **Teamcenter Connector - Implementations - Workflow**. With these microflows, you can retrieve workflow templates, submit item revisions to a workflow, and retrieve the tasks for a user's inbox. We also added microflows that act on workflow tasks, for example, to complete, suspend, resume, reassign, abort, and attach a reference or target. For attaching references, we introduced the `root_reference_attachments` relation. In addition, you can manage reviewers and signoffs: you can assign, add, or replace reviewers, claim signoffs assigned to a resource pool, and approve or reject signoffs. This means your Mendix app can act as an orchestration layer, with Teamcenter workflows as one part of a business process that spans multiple systems.

#### Service Document

* **Update Workspace Object** – The Teamcenter Service document now generates the domain model and artifacts for updating the properties of Workspace Objects in Teamcenter.

### Improvements

#### Connector

* When saving a Teamcenter configuration fails, the error message now shows the cause instead of the generic Mendix error.
* We changed the upload and download actions so they throw an error when something goes wrong, such as an FMS connection error, invalid input or incomplete data from Teamcenter, instead of failing silently.
* The toolbox exposed three "create BOM window" microflows. We removed one and gave the other two distinct exposed names.

#### Service Document

* We preselected the active module when configuring constants for secrets.
* We added a new consistency error for Teamcenter Service documents that reference domain models that no longer exist.
* We added a scrollbar to the integrations menu.

### Fixes

#### Connector

* We fixed an issue that made it impossible to upload files to Teamcenter with `UploadFiles` and `UploadTemporaryFiles` when using Teamcenter X authentication.
* We fixed an issue that made it impossible to download a file or image from Teamcenter when using Teamcenter X authentication.
* We now store the Teamcenter X access token encrypted.
* We updated `jackson-core` and `jackson-databind` from 2.22.2 to 2.22.3 to resolve a vulnerability.

#### Service Document

* We fixed a race condition when editing and generating integration microflows.
* We fixed the display order of the attributes of selected Teamcenter properties.
* We fixed an issue where you could select Teamcenter properties whose names are Mendix reserved words.
* We fixed an issue where the name of new associations could conflict with existing associations on specializations of the parent entity.
* We fixed an issue where generated microflows contained redundant cast actions.
* We updated Zod to version 4.6.7 to fix a performance bug.
* We fixed an issue with the height of the property mapping dialog box when the dialog box does not include a list of properties, relations, or references.

### Breaking Changes

#### Connector

* We upgraded the Teamcenter Connector to Studio Pro 11.12.4, so it now requires Studio Pro 11.12.4 or above.
* We changed `ExpandPSOneLevel2` so that it no longer creates FileDocuments when `DownloadFiles` is false.
* We removed support for comma-separated lists of FMS URLs.
* We deprecated the `TcConnector.task` association. It is replaced by the `TcConnector.actionableObject` association (`PerformAction3`). When upgrading, check all usages of the `TcConnector.task` association and replace them with `TcConnector.actionableObject`.

## 2606.0.0

**Release date:** July 31, 2026

{{% button color="info" href="https://marketplace.mendix.com/link/component/111627" text="Go to Marketplace" title="Download the Teamcenter Connector from the Marketplace" %}}

**Requirements:** Studio Pro 11.12.1 or above

Version 2606 of the Teamcenter Connector consolidates and modernizes Teamcenter integrations. The Teamcenter Connector now includes a new Studio Pro extension for configuring your integrations, a complete rebuild with many usability improvements. We consolidated everything into one place. Previously, you had to download the Teamcenter Connector module and the Teamcenter Extension (which contained Teamcenter Toolkit and the Extension as part of an add-on module) separately. Now there is a single download, a single import, and a single version to track. The Teamcenter Toolkit has been integrated into the TcConnector module, with all of its microflows, entities, and Java actions.

### New Features

#### Teamcenter Service Document

We introduced the Teamcenter Service document, a new design-time approach that changes how you build Teamcenter integrations. The Service document is your starting point and central hub for managing all integrations within a module. It replaces the previous menu-based Extension that stored configuration files on disk. The document contains two main sections:

* **Settings** tab where you configure your Teamcenter connection and authentication (with automatic credential clearing when connection details change for security).
* **Integrations** tab that provides an overview of all configured integrations, showing generated entities and microflows. From the **Integrations** tab, you can view, edit, duplicate, or delete integrations. You can create multiple Service documents within your app, each in a separate module. This enables you to organize integrations by concern (for example, separate documents for parts, workflows, and documents).

To create a Service document, right-click a module in the **App Explorer** and select **Add other** > **Teamcenter service**. Once configured, the Extension generates everything you need: entities, associations, create and revise input entities, and microflows. This keeps your integration artifacts organized and version-controlled alongside your other Mendix documents.

#### Mendix in AWC

We made some changes to the Teamcenter Connector that are required for embedding Mendix apps in Teamcenter Active Workspace Client (AWC). For more information, refer to [Mendix Inside Teamcenter](/refguide/mendix-client/mendix-inside-teamcenter/). These changes also give you more control over session management and authentication when building Mendix apps that integrate with Teamcenter:

* We added an optional session discriminator on `Login` and `LoginSSO`. `Credentials` now has a new discriminator field; empty means unchanged behavior. This allows an embedded Mendix component to maintain separate sessions when needed.
* We added a session discriminator on the `/tcsso/login` service, so an embedded Mendix component can now reuse the active AWC Teamcenter session.
* We introduced a new anonymous REST endpoint to check whether the current session is signed in to Teamcenter without requiring authentication.

### Improvements

#### TcConnector

* We hardened security by removing Create and Delete rights from all entities to align with security best practices. The Administrator role no longer has direct entity-level access (except for Teamcenter Configuration). For all Teamcenter integrations, use the User role.
* We improved single sign-on (SSO) configuration error logging. Messages now name the fields that may be wrong and match the Teamcenter Extension.
* We added a consistent Teamcenter icon on all published actions. Actions marked with a Teamcenter icon in Studio Pro are published and intended for your use. Actions without the icon are internal implementation details. Do not call them directly from your microflows.
* We upgraded to Mendix 11.12.1.
* We established clearer public and private boundaries in the structure of the TcConnector module. The Teamcenter Connector now has a well-defined public API.

#### Teamcenter Extension

* We rebuilt the Teamcenter Extension using the Mendix Web Extensibility Framework (TypeScript). Previously, it used the C# Extensibility Framework, which Mendix is discontinuing. This ensures continued compatibility with future Mendix releases.
* We redesigned the Teamcenter Extension to follow the Studio Pro Design System. As a result, the extension looks and feels more like a native part of Studio Pro than the C# extension did, and it is more consistent with the rest of your development environment.
* We introduced the Teamcenter Service document. This document stores your integrations in the Mendix model. You can create multiple Service documents per app or module. This enables you to organize your Teamcenter integrations by functional area (for example, a Parts module and a Workflows module can each have their own Service document) or by Teamcenter environment. An added benefit of the Teamcenter Service document is that integrations and Teamcenter instance settings are now stored as a document within your module, just like microflows and pages. The Teamcenter Service document is the new entry point for your Teamcenter integrations and replaces the previous menu-based extension that stored configuration files on disk.
* We introduced Teamcenter Service document consistency checks. The extension validates your integrations and shows consistency checks when your integration is corrupted. The extension listens to model changes to make sure the consistency checks remain in sync. The extension displays the consistency checks as warnings in the **Error List**. This also allowed us to clean up the UI of the integrations overview. Instead of showing warnings in the extension, we now refer you to the **Error List** when there are consistency errors.
* We removed the sidebar from the import mapping page. Instead, the extension uses dialog boxes for selecting properties and configuring integration-specific properties. This is more in line with Studio Pro.
* We added a button to the toolbar of the import mapping page to launch the property mapping dialog box for the selected business object or entity.
* We introduced constants to store the secrets used in the Teamcenter X SSO configuration for the Teamcenter Extension. This way, you can keep them secret and avoid committing them to version control.
* We added the option to clear the object mapping for a business object or entity by selecting it and pressing <kbd>Delete</kbd>.
* We added a new annotation to the Get structure integration that displays the integration-specific properties: which revision rule to use, whether variant rules are used, and whether BOM window properties are configured at design time.

### Fixes

* We improved the error message when the provided configuration name does not exist.
* We fixed a blocking (locked) state when calling multiple Teamcenter Java actions within one transaction. This issue could cause one locked user to prevent other users from executing Teamcenter operations.
* We fixed an error when a Teamcenter response contained an array mixing empty strings and valid Model Object UIDs. (Ticket 269666)
* We updated attributes on `BOMLine`, `ReviseItemRevision`, `User`, and `WorkspaceObject` entities to match Teamcenter defaults, reducing the chance of data truncation:
    * `BOMLine` `bl_rev_object_name` (128)
    * `BOMLine` `bl_quantity` (24)
    * `BOMLine` `bl_plmxml_abs_xform` (240)
    * `ReviseItemRevision.item_revision_id` (32)
    * `User.userid` (32)
    * `WorkspaceObject.checked_out` (32)
* We fixed `WhereUsed2` so that it correctly maps `clientId` and `level` in its response.
* We fixed a misleading error "Entity does not exist: ListOfValues" from `GetAttachedLOV` and `GetAttachedPropDescs2`.
* We renamed FileType/File Type to NamedReference/Named Reference for consistency with Teamcenter naming conventions.

### Breaking Changes

#### Resources Folder

* We changed the structure of the resources folder. All resources for the connector are now in the **Resources/TcConnector** folder.
* When upgrading, move all custom Operation Mapping JSON files to **Resources/TcConnector/OperationMapping** and remove the old Operation Mapping folder (**Resources/OperationMapping**).
* You can remove the **Resources/TeamcenterCommon** folder.
* You can remove the **Resources/TeamcenterConnector** folder.

#### Teamcenter Toolkit Integration

* We integrated the Teamcenter Toolkit content into the Teamcenter Connector. Its microflows, folders, and entities are now in the Connector under the same names. We merged the `BOMLine` entities and moved the search-criteria entities. Regenerate your integration with the Teamcenter Extension to resolve references to the microflows and entities.

#### Removed Actions

We removed the following microflow and Java actions. If they are still used in your project, retain the old `TeamcenterToolkit` module until you have migrated away from these actions:

* `ModelObject_AddToExistingOrNewList`
* `JA_CopyModelObjectToNewCreateInput`
* `JA_CreateDatasetSpecialization`
* The pre-configured `CreateBOMWindow` variants (`CreateBOMWindow_Default`, `CreateBOMWindow_RevisionRule`, `CreateBOMWindow_VariantRule`, and their combinations) – use `CreateBOMWindow` or `CreateBOMWindow_ByConfigurationContext` instead. We updated the `CreateBOMWindow` microflow: its parameters are now optional, and we split off a separate `ByConfigurationContext` variant for cases where you need that level of control.

#### Security Model

* We removed Create and Delete rights on all entities. The Administrator role now only has access to Teamcenter Configuration. Use the User module role for Teamcenter integrations.

#### Error Handling

* We changed the error handling behavior. The Connector no longer shows in-app error messages automatically. Instead, all error conditions throw exceptions, giving your microflows full control over how to handle and present errors to users.

#### Configuration Requirements

* We fixed a bug where providing a `ConfigurationName` to Java actions changed the behavior. The `ModelObject` Java class now consistently requires `ConfigurationName` to be set in all cases. Previously, the behavior varied depending on whether you passed a configuration name.

#### Entity Changes

* We removed the `LastError` attribute from the `Credentials` entity. Use exception handling instead.
* We introduced a new naming convention for `CreateInput` and `CompoundCreateInput` specializations generated by the Teamcenter Service document. If you have existing integrations, you must regenerate them by creating a new Teamcenter Service document, configuring your integration, and generating the artifacts. Regeneration does not delete your previous input entities, so remove them manually.
