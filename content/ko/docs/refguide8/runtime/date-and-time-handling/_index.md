## 소개

Mendix Server 작업은 서버 시간대 대신 사용자의 시간대를 사용합니다. 이전에는 문서 생성, Excel/CSV 내보내기 및 Microflow/OQL의 날짜 계산과 같은 작업이 모두 서버 시간대를 사용했습니다. 서버와 애플리케이션의 모든 사용자가 동일한 시간대에 있는 경우에는 괜찮습니다. 그렇지 않은 경우 생성된 출력에 예상치 못한 결과가 포함될 수 있습니다.

## 관련 시간대

Mendix 애플리케이션에서는 세 가지 시간대가 관련됩니다:

1. 사용자/클라이언트: 클라이언트가 실행되는 시간대는 최종 사용자에게 날짜와 시간을 표시하는 데 사용됩니다. 시간대는 일광 절약 시간(DST)을 올바르게 처리하기 위해 이제 (선택적으로) 각 사용자와 함께 저장됩니다. 시간대가 설정되지 않으면 일광 절약 시간(DST)이 적용되지 않습니다.
2. 협정 세계시(UTC): 플랫폼은 모든 날짜를 UTC 시간대에 저장합니다. 이것은 모호하지 않은 날짜 형식을 제공하기 위해 서버에서 자주 사용되는 시간 표준입니다. 계절 변화(DST)에 따라 변경되지 않습니다. 날짜나 시간이 사용자에게 표시될 때마다 달리 지정하지 않는 한 클라이언트의 시간대로 현지화됩니다.
3. 서버: 서버가 실행되는 시간대는 Scheduled Event가 실행되는 시간을 스케줄링하는 데만 사용됩니다. Scheduled Event를 정의할 때 서버 시간 또는 UTC 시간을 사용할지 선택할 수 있습니다. 그 외의 모든 것에서 서버 시간은 관련이 없습니다.

간결함을 위해 이 시간대들을 사용자 시간, UTC, 서버 시간이라고 부르겠습니다.

## 변경 사항

서버는 각 사용자의 시간대를 알아야 합니다. 안타깝게도 웹 브라우저는 이 정보를 보고할 수 없습니다. 현재 UTC에 대한 오프셋만 보고합니다. 이것은 정확한 시간대를 결정하고 미래 및 과거 날짜의 일광 절약 시간을 올바르게 처리하기에 충분하지 않습니다. 이러한 이유로 웹 애플리케이션은 종종 시간대를 설정하는 옵션을 제공하며, 이제 Mendix에도 이 옵션을 내장했습니다. 각 사용자에 대해 시간대를 명시적으로 설정할 수 있으며, 이 시간대가 서버 작업에 사용됩니다.

TimeZone Entity가 User와 TimeZone 간의 Association과 함께 System 모듈에 추가되었습니다. TimeZone Entity에는 세 가지 Attribute가 있습니다: 코드(Olson 데이터베이스 기반), 사용자에게 표시하기에 적합한 설명("(GMT-05:00) New York"), 시간대 목록을 정렬하는 데 사용되는 원시 오프셋.

Administration 모듈에서 Account_NewEdit 페이지는 사용자의 시간대를 설정하기 위한 시간대 선택기를 추가합니다. 기본적으로 MyAccount 페이지에는 이 선택기가 없습니다. 관리자가 시간대를 올바르게 설정하는 것이 관리자의 임무입니다. 최종 사용자가 직접 시간대를 설정할 수 있도록 하려면 직접 추가할 수 있습니다.

Studio Pro는 프로젝트 Settings 대화 상자에 설정을 추가합니다. 'Model' 탭에서 기본 시간대를 지정할 수 있습니다. 이 시간대는 새 사용자에게 사용되지만 애플리케이션을 시작할 때 아직 시간대가 없는 모든 사용자에게도 적용됩니다.

## 기존 프로젝트

새로운 날짜/시간 처리를 활용하려면 기존 프로젝트를 변환한 후 일부 작업을 수행해야 합니다. 이러한 작업은 프로젝트의 유형에 따라 다릅니다: 단일 시간대 또는 다중 시간대. 단일 시간대 프로젝트에서는 모든 사용자가 동일한 시간대에 있거나 적어도 동일한 시간대를 사용할 의향이 있습니다. 서버의 시간대는 중요하지 않으므로, 모든 사용자가 네덜란드에 있지만 서버가 영국에 있는 경우에도 프로젝트는 여전히 단일 시간대입니다. 다중 시간대 프로젝트에는 서로 다른 시간대의 사용자가 있습니다. 각 경우에 수행해야 할 작업을 살펴보겠습니다.

### 단일 시간대 프로젝트

서버도 해당 시간대에 있는 단일 시간대 프로젝트에서 아무것도 하지 않으면, 서버 작업에 대한 상황은 실제로 이전보다 약간 나빠집니다. 사용자에게 시간대가 없으며, 이 경우 서버는 웹 브라우저가 보고하는 UTC에서의 현재 오프셋을 사용합니다. 이 오프셋은 정확한 시간대를 결정하기에 충분하지 않으며, 이는 일광 절약 시간(DST)이 고려되지 않음을 의미합니다. 실제로 이는 DST 변경 이후의 미래 및 과거 날짜와 시간이 한 시간 차이가 난다는 것을 의미합니다.

모든 사용자의 시간대가 설정되도록 하려면 Studio Pro의 프로젝트 설정에서 기본 시간대를 설정해야 합니다. 애플리케이션이 다시 시작되면 모든 기존 사용자가 이 기본 시간대를 갖게 됩니다. 또한 새 사용자가 생성될 때도 자동으로 이 기본 시간대를 갖게 됩니다.

요약하면, 단일 시간대 프로젝트에서는 Studio Pro에서 기본 시간대를 설정하기만 하면 됩니다.

### 다중 시간대 프로젝트

다중 시간대 프로젝트에서 아무것도 하지 않으면 서버 작업에 대한 상황은 자동으로 개선됩니다. 이전에는 서버 시간대가 Excel 내보내기 및 기타 문서 생성과 같은 작업에 사용되었습니다. 이는 중국의 사용자가 보고서를 생성하고 서버가 미국에 있는 경우 날짜와 시간이 크게 차이가 났음을 의미합니다. 서버는 이제 최소한 브라우저의 UTC 오프셋을 사용합니다. 일광 절약 시간만 아직 올바르게 처리되지 않습니다. 적절한 DST 처리를 위해서는 사용자의 시간대를 설정해야 합니다.

다중 시간대 프로젝트에서 수행할 수 있는 여러 가지 방법이 있습니다:

* 아무것도 하지 않기. 아무것도 하지 않으면 서버 작업은 사용자의 현재 UTC 오프셋을 사용하며, 이는 실제로 시간대를 설정하는 것의 합리적인 근사치입니다. DST만 올바르게 처리되지 않습니다.
* 사용자가 직접 시간대를 설정할 수 있도록 허용. 사용자가 자신의 계정을 관리할 수 있는 페이지에 시간대 참조 선택기를 추가하십시오(기본적으로 Administration의 MyAccount). 이때 시간대는 사용자가 로그아웃하고 다시 로그인한 후에만 효과적으로 업데이트된다는 점에 유의하십시오.
* 관리자가 시간대를 설정. 관리자가 계정을 관리하는 페이지에 시간대 참조 선택기를 추가하십시오(기본적으로 Administration의 Account_NewEdit). 애플리케이션에 사용자가 많지 않은 경우 이것은 실행 가능한 솔루션입니다.
* Microflow를 사용하여 자동으로 시간대 설정. 애플리케이션이 소수의 시간대에서 사용되고 어떤 사용자에게 어떤 시간대를 설정해야 하는지 자동으로 결정할 수 있는 경우, After Startup Microflow를 작성하여 시간대를 설정할 수 있습니다. 예를 들어, 애플리케이션이 미국과 네덜란드에서 사용되고 미국의 모든 사용자가 언어를 미국 영어로 설정하고 네덜란드의 모든 사용자가 언어를 네덜란드어로 설정한 경우, Microflow가 모든 사용자를 순회하며 사용자의 언어 코드를 기반으로 시간대를 설정할 수 있습니다.

{{% alert color="warning" %}}
다중 시간대 프로젝트에서는 Studio Pro의 기본 시간대 설정을 사용하지 마십시오. 모든 사용자에게 기본 시간대가 설정되기 때문입니다!
{{% /alert %}}

## 익명 사용자

로그인하지 않고 애플리케이션에 접근할 수 있는 경우, 익명 사용자는 Studio Pro에서 설정된 기본 시간대를 갖게 됩니다. Studio Pro에서 시간대가 설정되지 않은 경우 브라우저가 보고하는 오프셋을 사용합니다. 미래와 과거 날짜에 대한 DST만 올바르게 처리되지 않습니다.

## 현지화할 것인지 말 것인지

**Date and time** 유형의 Attribute별로 날짜와 시간을 현지화할지 여부를 지정할 수 있습니다. 이것은 새로운 기능은 아니지만 이 페이지에서 언급할 가치가 있습니다. 현지화된 Attribute와 현지화되지 않은 Attribute 모두 UTC로 저장되지만, 현지화된 Attribute만 값을 표시할 때 사용자의 시간대로 변환됩니다. 시간 구성 요소에 관심이 없는 경우(예: 생일) 또는 전 세계에서 날짜가 정확히 동일하게 보이길 원하는 경우 현지화되지 않은 Attribute를 사용하십시오.

자세한 내용은 [Attribute](/refguide8/attributes/)의 Localize 속성 문서를 참조하십시오.

## 토큰

[%BeginOfCurrentDay%]와 같은 특정 시점을 참조하는 토큰은 이제 사용자 시간대를 참조합니다. 의미가 있는 경우 UTC 버전의 토큰이 추가되었습니다(예: [%BeginOfCurrentDayUTC%]).
