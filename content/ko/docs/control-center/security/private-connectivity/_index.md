## 소개

**프라이빗 연결** 페이지에서는 회사의 프라이빗 연결 자산(네트워크, 에이전트, 리소스, 연결)을 보고 관리할 수 있습니다.

{{% alert color="info" %}}
**프라이빗 연결** 페이지에 접근할 수 없는 경우 CSM 또는 Mendix 지원팀에 문의하십시오.

## 사용 사례

Mendix Cloud에서 실행되는 많은 앱은 데이터베이스, 서비스 및 기타 애플리케이션과 같은 외부 리소스와 통합됩니다. 이러한 리소스 중 일부는 공개 인터넷을 통해 접근할 수 있는 공개 리소스입니다. 다른 리소스는 온프레미스 또는 클라우드 인프라에서 PaaS/SaaS로 내부 네트워크에서 실행됩니다. 공개 인터넷을 통해 이러한 리소스에 연결하고 HTTPS, 리버스 프록시 및 클라이언트 인증서로 [보안](/developerportal/deploy/securing-outgoing-connections-from-your-application/)할 수 있습니다. 이 시나리오에서는 내부 리소스를 공개 인터넷에 노출해야 합니다. 그러나 보안, 규정 준수 또는 레거시 이유로 모든 사람이 이를 원하거나 할 수 있는 것은 아닙니다.

Mendix Cloud 프라이빗 연결을 사용하면 Mendix 앱을 내부 리소스에 안전하고 비공개적으로 연결할 수 있습니다. 이는 연결이 공개 인터넷을 통하지 않고 Mendix 앱과 자체 인프라 간의 프라이빗 터널을 통해 이루어짐을 의미합니다. 이것은 온프레미스 데이터 센터 또는 AWS, Azure, GCP와 같은 클라우드 인프라일 수 있습니다. 서로 다른 인프라에서 실행되는 여러 네트워크를 연결할 수도 있습니다.

Mendix Cloud 프라이빗 연결은 아웃바운드 연결만 지원합니다. 즉, Mendix 앱에서 자체 인프라의 리소스로 시작되는 연결입니다. 프라이빗 터널을 통해 외부 클라이언트에서 Mendix Cloud 앱에 연결할 수는 없습니다.

프라이빗 연결을 사용하면 내부 리소스를 공개 인터넷에 노출하지 않고도 다음과 같은 작업을 안전하고 비공개적으로 수행할 수 있습니다:

* Azure의 Microsoft SQL 데이터베이스에서 Mendix 앱으로 데이터 검색
* 자체 AWS 계정에서 실행되는 Kafka 브로커에 연결
* 온프레미스 데이터 센터에서 실행되는 SAP 시스템에 연결

## Tailscale {#private-connectivity-tailscale}

Mendix는 [Tailscale](https://tailscale.com)과 파트너십을 맺고 프라이빗 연결을 제공합니다. Tailscale은 WireGuard® 프로토콜의 고성능 및 현대적 암호화를 기반으로 구축된 안전한 프라이빗 메시 네트워크 솔루션을 제공하는 보안 네트워킹의 인정된 리더입니다. Mendix는 Tailscale 플랫폼에서 프라이빗 연결을 생성하는 데 필요한 모든 자산을 생성합니다. Tailscale이나 Mendix 모두 Tailscale 네트워크를 통해 전송되는 데이터에 액세스할 수 없습니다. 모든 트래픽은 각 네트워크에 대한 별도의 키와 공개 키 인프라로 엔드 투 엔드 [암호화](https://tailscale.com/kb/1504/encryption)됩니다.

## 아키텍처 {#private-connectivity-architecture}

다음 섹션에서는 프라이빗 연결 아키텍처를 구성하는 구성 요소에 대한 개요를 제공합니다.

### 네트워크

Mendix는 Tailscale에 엔터프라이즈 계정을 가지고 있습니다. Mendix 소유의 Tailscale 계정 내에서 Mendix는 전용 프라이빗 연결 네트워크를 생성합니다. 예를 들어 프로덕션 트래픽을 비프로덕션 트래픽과 격리하려는 경우 여러 네트워크를 가질 수 있습니다.

### 에이전트

다음으로, 자체 인프라에 에이전트를 설치해야 합니다. 이러한 에이전트는 Mendix가 생성한 프라이빗 연결 네트워크에 아웃바운드 연결을 시작하는 연결 도구입니다.

에이전트는 Mendix 플랫폼에서 관리되는 인증 키가 필요하며, 인증 키가 연결된 네트워크에만 연결할 수 있습니다.
각 에이전트는 연결하려는 리소스에 액세스할 수 있는 서버에 설치해야 합니다.

에이전트는 단일 프라이빗 연결 네트워크에 연결할 수 있지만, 동일한 프라이빗 연결 네트워크에 연결하는 여러 에이전트를 설치할 수 있습니다. 예를 들어, 온프레미스 데이터 센터에 에이전트를 설치하고 AWS 계정에 다른 에이전트를 설치하여 Mendix 앱이 두 인프라의 리소스에 연결할 수 있습니다.

### 리소스

에이전트가 설치되면 이를 사용하여 리소스를 노출해야 합니다. 이러한 리소스는 네트워크의 서브넷입니다. 에이전트를 통해 사용할 수 있으며 공개 인터넷을 통해서는 사용할 수 없습니다.

에이전트를 통해 노출된 리소스는 Mendix 앱이 연결하기 전에 항상 Mendix 플랫폼에서 활성화해야 합니다. 이를 통해 어떤 리소스에 접근할 수 있는지 완전히 제어할 수 있습니다.

### 연결

리소스가 노출되고 활성화되면 연결을 추가할 수 있습니다. 연결은 특정 앱 환경을 특정 리소스에 연결합니다.

연결은 요청해야 합니다. 승인된 경우에만 Mendix 앱이 연결 반대편의 리소스에 연결할 수 있습니다. 이 4-eye 원칙은 연결에 대한 거버넌스를 허용하여 어떤 앱 환경이 어떤 리소스에 접근할 수 있는지 완전히 제어할 수 있습니다. 승인된 연결은 언제든지 비활성화하여 앱 환경에서 리소스에 대한 액세스를 취소할 수 있습니다.

각 앱 환경에 대해 여러 연결을 추가하여 온프레미스 데이터 센터의 리소스와 AWS 계정의 리소스에 대한 액세스를 부여할 수 있습니다.

Mendix는 하나 이상의 승인된 연결이 있는 각 앱 환경의 앱 컨테이너에 Tailscale 에이전트를 설치합니다. Tailscale 에이전트가 앱 컨테이너 내에서 실행되므로 해당 특정 앱만 네트워크 및 승인된 연결에 액세스할 수 있습니다.

## 자주 묻는 질문 {#private-connectivity-faq}

### Mendix나 Tailscale이 내 데이터에 접근할 수 있나요?

아니요. Tailscale 네트워크를 통해 전송되는 모든 데이터는 각 네트워크에 대한 별도의 키와 공개 키 인프라로 엔드 투 엔드 [암호화](https://tailscale.com/kb/1504/encryption)됩니다. Tailscale이나 Mendix 모두 Tailscale 네트워크를 통해 전송되는 데이터에 액세스할 수 없습니다.

### Tailscale은 SOC2를 준수하나요?

예, Tailscale은 [SOC 2 Type II 인증](https://tailscale.com/security)을 완료했습니다.

### 자체 Tailscale 계정에 가입해야 하나요?

아니요, Tailscale 계정에 직접 가입할 필요가 없습니다. Mendix Cloud 프라이빗 연결에 필요한 모든 자산은 Mendix Tailscale 계정 내에서 생성됩니다. 이는 Mendix Cloud에서 앱을 실행하는 데 필요한 모든 리소스를 Mendix AWS 계정에서 생성하는 것과 유사합니다.

### 기존 Tailscale 네트워크를 연결할 수 있나요?

현재 기존 Tailscale 고객인 경우 기존 Tailnet에 연결하는 것은 불가능합니다.
