## 2.0.0

이 릴리스에서는 SDK API에 여러 호환성 변경 사항이 도입되었으므로, 시맨틱 버전 관리에 따라 메이저 버전을 올려야 합니다.

| story# | 영향도 | 설명 |
| --- | --- | --- |
| 612773 | 높음 | 모델 엘리먼트의 포함 메커니즘이 재작업되었습니다: 자세한 내용은 아래를 참조하세요. |
| 634662 | 낮음 | 엘리먼트와 유닛의 `toPlainJson` 메서드가 `toJSON`으로 이름이 변경되었습니다. 예를 들어 Chrome Developer Tools가 이를 이해하여 이러한 객체의 보기 좋은 사람이 읽을 수 있는 표현을 생성합니다. 코드를 수정하려면 `toPlainJson`의 모든 사용을 `toJSON`으로 변경하세요. |
| 639825 | 낮음 | 대상이 모델에 다시 추가되면 깨진 이름 참조가 자동으로 수정됩니다. |
| 637545 | 없음 | 향후 Mendix 6.3.0에 대한 마이너 내부 수정 사항입니다. |
| 633932 | 없음 | SDK에 장기 워킹 카피(24시간 후 삭제되지 않는) 지원을 추가하였습니다. 이것은 현재 신뢰할 수 없는 백엔드에서는 사용할 수 **없습니다**! |
| 620108 | 없음 | 내부 네임스페이스에서 내보낸 `IObservable` 인터페이스를 제거하고 `MObservable` 라이브러리의 것으로 대체하였습니다. |

다음 **호환성을 깨뜨리는** 변경 사항은 612773에 따라 이루어졌으며, Mendix 모델링 언어의 버전 관리/히스토리와 포함 간의 간섭에 대한 새로운 통찰의 결과입니다.
이 간섭으로 인해 엘리먼트가 히스토리 전체에서 다양한 종류의 포함을 갖게 됩니다.
이로 인해 향후 호환성 변경을 피하기 위해 근본적인 변경이 필요하였습니다.

* `container` 속성은 더 이상 엄격한 타입이 아닙니다. 예를 들어, `domainmodels.Attribute.container`는 더 이상 `Entity` 타입이 아니라 일반 `Container` 타입입니다.
* 대신 타입 `T`의 `containerAs<T>` 속성이 모든 엘리먼트에 도입되었습니다. 이 속성은 엘리먼트를 포함하는 `T`의 인스턴스를 반환하거나, `T`의 인스턴스에 포함되지 않은 경우 예외를 발생시킵니다. 이러한 예외를 피하려면 `container`를 `instanceof` 가드와 함께 사용하세요.
* 엘리먼트가 *여러* 속성에 의해 포함되는 경우(즉, 1개 이상), 주어진 `T`의 인스턴스에서 속성 `P` 아래에 새 엘리먼트를 생성하는 `createIn<T>Under<P>` 메서드가 생성됩니다. 이전에 존재하던 여러 `createIn` 메서드는 1개의 포함 속성만 고려했던 `createIn<T>Under<P>` 메서드로 대체되었습니다.
* 하나 이상의 버전에서 하나의 속성에 의해 포함되는 엘리먼트는 해당 버전에서 예상대로 작동하는 `createIn` 메서드를 가지며 다른 버전에서는 예외를 발생시킵니다.
* 항상(즉, 모든 버전에서) 파생된 속성에 의해 포함되는 엘리먼트는 `createIn...` 메서드가 없습니다.

종속 코드는 `container` 속성 대신 `containerAs<T>` 속성을 사용하고, (일부 특정 경우에) `createIn` 메서드 대신 `createIn<T>Under<P>` 메서드를 사용하여 쉽게 수정할 수 있습니다.
