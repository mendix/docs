## 소개

이 문서는 레이아웃과 스니펫을 사용하여 페이지를 만드는 기본 사항을 다룹니다.

이 하우투에서 배울 수 있는 내용:

* 스타일 레이아웃 만들기
* 스니펫 만들기

## 레이아웃

이 섹션에서는 레이아웃의 구성 요소와 그 가치에 대해 설명합니다.

### 페이지 구성 요소

페이지를 보면 페이지가 두 가지 중요한 구성 요소로 이루어져 있음을 알 수 있습니다:

* 레이아웃 — 페이지의 구조(PowerPoint에 하나 이상의 레이아웃 프리셋이 있는 것처럼)
* 콘텐츠 — 페이지 구조 내에 표시되는 내용

페이지를 모델링할 때 페이지가 생성될 때 레이아웃을 선택합니다.

### 레이아웃의 가치

레이아웃은 사용자 인터페이스를 구조화하는 데 사용됩니다. 기본 페이지 구조를 정의하여 페이지의 템플릿으로 재사용할 수 있게 합니다. 이 구조를 통해 애플리케이션이 최종 사용자에게 표시되는 방식을 설계할 수 있습니다. 모범 사례는 앱 모델링을 시작하기 전에 UI 구조를 사전 정의하는 것입니다. 빈 레이아웃도 있지만, 이는 레이아웃의 기본 설정이며 미리 정의된 레이아웃 구조도 사용할 수 있습니다.

사용 가능한 미리 정의된 레이아웃 구조는 다음과 같습니다:

* DesktopLayout
    * 로고와 메뉴 바가 있는 헤더 표시용
    * 콘텐츠 플레이스홀더 사용
    * 텍스트가 있는 푸터 사용
* PopupLayout
    * 콘텐츠 플레이스홀더만 포함

대부분의 사용자는 데스크탑 사용자를 위한 애플리케이션 인터페이스를 먼저 만들지만, 모바일 및 태블릿 사용자를 위해 앱을 쉽게 확장할 수 있습니다. 각 기기에 대해 특정 기기 유형의 레이아웃 요구에 맞는 레이아웃 세트를 만들 수 있습니다. 기기별 레이아웃이 생성되면 기기별 페이지를 만드는 템플릿으로 사용할 수 있습니다:

## 스타일링

레이아웃 외에도 애플리케이션은 고객 브랜드에 맞는 색상 체계와 같은 특정 외관과 느낌을 가져야 합니다. 이는 CSS/Bootstrap과 CSS 파일을 통해 Mendix 페이지 요소에 연결된 미리 정의된 클래스 세트로 달성됩니다. 애플리케이션 디자인의 이 부분은 많은 유연성을 허용하지만, 고급 과정이며 특정 CSS 및 HTML 지식이 필요합니다. 이 하우투의 현재 범위에서는 기본 스타일링을 사용합니다.

### 새 레이아웃 만들기

이미 언급했듯이 기본 앱 개발 시 만나는 기본 요구를 충족하는 미리 정의된 레이아웃 세트가 제공됩니다. 그러나 더 정교한 앱을 원할 경우 더 고급 레이아웃 설정이 필요할 수 있습니다. 다음 섹션에서는 새 레이아웃 만들기의 기본 사항을 설명합니다.

### 레이아웃 위젯

이 섹션에서는 새 레이아웃 생성에 사용되는 주요 요소를 설명합니다. 이후 기본 디자인 접근 방식이 논의됩니다.

#### 레이아웃 컨테이너

레이아웃 컨테이너는 레이아웃을 헤더, 사이드바, 푸터와 같은 영역으로 나누는 데 사용됩니다. 레이아웃 컨테이너는 유일한 최상위 위젯이어야 합니다. 또한, 레이아웃 컨테이너는 다른 레이아웃 컨테이너 내에 직접 배치될 수만 있습니다.

#### 영역

영역을 사용하면 레이아웃 컨테이너를 섹션으로 나누어 특정 고정 위치에 레이아웃 요소를 배치할 수 있습니다. 각 영역에는 플레이스홀더 또는 특정 위젯이 포함됩니다.

#### 플레이스홀더

플레이스홀더는 레이아웃에서 해당 레이아웃을 기반으로 한 페이지에서 채울 수 있는 영역을 정의하는 데 사용하거나 해당 레이아웃을 기본 레이아웃으로 정의하는 다른 레이아웃에서 사용할 수 있습니다.

{{< figure src="/attachments/howto/front-end/layouts-and-snippets/placeholders.png" class="no-border" >}} 

페이지에서 영역이 채워지면 이것이 해당 페이지의 콘텐츠 영역이 되어 해당 페이지에 지정된 동적 데이터를 표시합니다. 레이아웃이 다른 레이아웃에서 상속되는 경우, 이 특수화된 레이아웃을 정의하기 위해 새 레이아웃 컨테이너로 영역을 채울 수 있습니다. 비워둘 수도 있으며, 그러면 페이지에서 채워집니다.

#### 상속

레이아웃은 다른 레이아웃을 기반으로 할 수도 있으며, 이 맥락에서 "기본 레이아웃"이라고 합니다. 레이아웃이 기본 레이아웃을 기반으로 하는 경우, 레이아웃은 기본 레이아웃에서 정의한 영역을 채우고 플레이스홀더를 사용하여 새 영역을 정의할 수 있습니다. 기본 레이아웃을 기반으로 한 레이아웃을 사용하는 페이지에는 기본 레이아웃의 영역이 아닌 레이아웃에서 정의한 영역만 표시됩니다.

## 데스크탑, 태블릿, 또는 모바일?

모든 페이지는 모든 기기 유형에서 열 수 있습니다. 생성된 HTML이 HTML5이기 때문입니다. 그러나 각 기기에는 고유한 UI 디자인 요구가 있습니다. 따라서 특정 기기 유형의 요구를 충족하는 기기 유형별 레이아웃 세트를 정의하는 것이 논리적입니다.

기본적으로 데스크탑과 폰 레이아웃이 기본 제공되며, 레이아웃의 디자인은 필요에 맞게 맞춤화할 수 있습니다. 기본 레이아웃을 변경하고 확장할 수 있으며, 필요에 따라 새 레이아웃을 만들 수도 있습니다.

이러한 레이아웃을 설계할 때 주의해야 합니다. 예를 들어, 모바일 앱에서는 너무 많은 영역을 두면 디자인이 혼잡하고 최종 사용자에게 혼란스러울 수 있습니다. 반면에 데스크탑 애플리케이션은 더 많은 콘텐츠를 표시하고 세부 사항을 표시할 수 있는 다른 영역이 필요할 수 있습니다.

레이아웃 컨테이너(또는 컨테이너들)로 레이아웃의 구조를 정의한 후 영역의 콘텐츠를 정의해야 합니다. 이는 페이지별로 페이지 고유 요소(예: 빈 영역에 데이터 컨테이너 추가)를 사용하거나, 이 레이아웃을 사용하는 각 페이지에서 사용될 요소를 정의하기 위해 레이아웃 내에서 수행할 수 있습니다. 일반적으로 이는 일반 앱 내비게이션 또는 특정 기능에 대한 특정 내비게이션이 됩니다. 데이터 및 입력 요소를 제외한 모든 위젯을 사용할 수 있습니다(소스가 필요하기 때문).

가장 유용한 위젯 유형 두 가지는 메뉴 및 내비게이션과 스니펫입니다. 아래에서 이 두 유형에 대해 자세히 알아볼 수 있습니다.

## 메뉴와 내비게이션

### 메뉴 바

메뉴 바 위젯은 구성된 메뉴를 항목이 있는 수평 바 형태로 표시합니다. 항목에는 하위 항목이 있을 수 있으며 메뉴의 주요 항목을 확장할 수 있습니다. 하위 항목은 한 단계만 들어갈 수 있습니다(하위 항목에 자체 하위 항목이 있을 수 없음). 메뉴 항목은 클릭했을 때 열리거나 시작되는 페이지 또는 Microflow를 가리킵니다.

{{< figure src="/attachments/howto/front-end/layouts-and-snippets/menu-bar.png" class="no-border" >}}

### 내비게이션 트리

내비게이션 트리 위젯은 구성된 메뉴를 트리 형태로 표시합니다. 주요 항목을 확장하면 항목에 하위 항목이 있을 수 있습니다. 내비게이션 트리의 메뉴 구조는 최대 세 단계까지 가능합니다. 결국, 메뉴 항목은 클릭했을 때 열리거나 시작되는 페이지 또는 Microflow를 가리킵니다.

{{< figure src="/attachments/howto/front-end/layouts-and-snippets/nav-tree.png" class="no-border" >}}

### 간단한 메뉴 바

간단한 메뉴 바 위젯은 구성된 메뉴를 이미지와 캡션이 있는 수평 바 형태로 표시합니다. 항목에는 하위 항목이 있을 수 없습니다(메뉴 구조는 한 단계만 가능). 메뉴 항목은 클릭했을 때 열리거나 시작되는 페이지 또는 Microflow를 가리킵니다.

{{< figure src="/attachments/howto/front-end/layouts-and-snippets/simple-menu.png" class="no-border" >}}

### 메뉴 소스

메뉴 위젯에 표시되는 항목은 메뉴 소스에 의해 결정됩니다. 메뉴 위젯은 **Navigation** 문서에 구성된 메뉴 또는 **Menu** 페이지 리소스에서 채워집니다:

* **App** > **Navigation** — 선택 시, 이 문서에 정의된 메뉴 중 하나에서 메뉴 항목을 가져옵니다. 이를 애플리케이션의 메인 메뉴에 사용하세요
* **Add Other** > **Menu** — 선택 시, 이 페이지 리소스에서 메뉴 항목을 가져옵니다. 이 메뉴를 보조 메뉴에 사용하세요

앱 내비게이션을 소스로 선택한 경우 올바른 내비게이션 메뉴에 대한 기기 프로필을 결정해야 합니다:

{{< figure src="/attachments/howto/front-end/layouts-and-snippets/edit-menu-bar.png" class="no-border" >}}

데스크탑의 경우 **Responsive** 메뉴를 사용하세요.

태블릿 및 폰 구성의 경우 적절한 프로필 유형을 선택해야 합니다. 자세한 내용은 아래 [기기 프로필](#profiles) 섹션을 참조하세요.

### 앱 내비게이션

**Navigation** 문서는 최종 사용자를 위한 애플리케이션의 주요 내비게이션 구조를 정의합니다. 애플리케이션의 홈 페이지를 설정하고 메뉴 및 내비게이션 위젯에서 사용할 메뉴 구조를 정의할 수 있습니다. 홈 페이지는 사용자가 가진 역할에 따라 다를 수 있습니다. 보안이 활성화된 경우, 메뉴는 사용자가 접근할 수 있는 항목만 표시합니다.

### 기기 프로필 {#profiles}

Mendix의 내비게이션 모델 중심에는 Desktop, Tablet, Phone의 세 가지 기기 유형이 있습니다. 이 세 기기에 대해 별도의 홈 페이지와 메뉴를 정의할 수 있습니다. Desktop 기기 유형은 항상 활성화되어 있으며, 다음 Tablet 및 Phone 프로필을 활성화하거나 비활성화할 수 있습니다:

* **Responsive web**
* **Responsive web offline**
* **Tablet web**
* **Tablet web offline**
* **Phone web**
* **Phone web offline**
* **Native mobile (tablet & phone)**

{{< figure src="/attachments/howto/front-end/layouts-and-snippets/device-profiles.png" class="no-border" >}}

사용자가 Mendix 애플리케이션을 방문하면 적절한 기기 유형의 홈 페이지로 자동 리디렉션됩니다(자세한 내용은 [기기 유형으로의 리디렉션](#RedirectiontoDeviceTypes) 섹션 참조).

내비게이션 프로필에 대한 자세한 내용은 [Mendix의 내비게이션](/refguide/navigation/)을 참조하세요.

### 메뉴 문서

메뉴 문서는 메뉴 위젯에서 사용할 수 있는 내비게이션 메뉴를 정의합니다. 일반적으로 애플리케이션의 메인 메뉴는 기기 유형에서 정의되며, 보조 메뉴(예: 사이드바)에는 메뉴 문서를 사용합니다. 메뉴는 선택적으로 하위 항목을 포함하는 메뉴 항목 목록으로 구성됩니다. 위젯에 따라 여러 단계가 허용됩니다.

{{< figure src="/attachments/howto/front-end/layouts-and-snippets/menu-document.png" class="no-border" >}}

### 기기 유형으로의 리디렉션 {#RedirectiontoDeviceTypes}

Mendix Runtime은 사용 중인 기기에 따라 사용자를 적절한 기기 유형의 홈 페이지로 자동 리디렉션합니다. 이는 기기의 브라우저가 보내는 `User-Agent` 문자열을 검사하여 이루어집니다. 다음은 리디렉션의 기본 구성입니다:

| User-Agent 문자열 정규식                | 기기 유형   |
| ------------------------------------ | ----------- |
| `Android.*Mobile` 또는 `iPhone`      | Phone       |
| `Android` 또는 `iPad`                | Tablet      |
| (기타)                               | Desktop     |

특정 사용자 인터페이스에 대한 문자열은 서버 사용자 정의 설정 내에서도 구성할 수 있습니다(이는 더 고급이며 여기서는 다루지 않습니다).

기기 유형이 활성화되지 않은 경우 다른 기기 유형으로 폴백됩니다:

| 기기 유형    | 폴백                                 |
| ----------- | ------------------------------------ |
| Phone       | Tablet, Desktop                      |
| Tablet      | Phone, Desktop                       |
| Desktop     | (없음, Desktop은 항상 활성화됨)       |

Mendix 애플리케이션 방문 시 URL에 `profile` 쿼리 문자열 매개변수를 추가하여 클라이언트가 특정 기기 유형을 사용하도록 강제할 수도 있습니다. 가능한 값은 `Desktop`, `Tablet`, `Phone`입니다.

## 스니펫

스니펫은 페이지와 레이아웃에서 사용할 수 있는 재사용 가능한 인터페이스 부분입니다. 스니펫을 사용하면 Mendix 비즈니스 엔지니어가 인터페이스에서 수정해야 할 곳이 줄어들고 더 원활한 전환과 사용자 친화적인 경험이 가능해집니다. 예를 들어, 템플릿 그리드의 콘텐츠 영역과 데이터 뷰 모두에서 사용되는 스니펫을 가질 수 있습니다. 스니펫에 대한 변경 사항은 스니펫이 사용되는 모든 곳에 적용됩니다.

또한, 스니펫은 그 안에 배치된 위젯의 맥락 역할을 하는 Entity를 정의할 수 있습니다. 예를 들어, 스니펫에 *Course* Entity를 설정하면 데이터 뷰를 먼저 정의하지 않고도 스니펫에 *Course Title*을 표시하는 텍스트 박스를 배치할 수 있습니다. 스니펫에 Entity가 정의된 경우, 스니펫을 사용하는 각 위치에서 해당 Entity의 맥락(예: 데이터 뷰) 안에 배치해야 합니다.
