## December 2019

### December 23, 2019

#### Improvements

* Mendix Cloud 배포의 안정성과 성능을 개선했습니다. (Tickets 86800, 92241, 92426)

## November 2019

### November 21, 2019

#### Improvements

* 배포 문제가 있을 때 Mendix Support가 더 나은 지원을 제공할 수 있도록 여러 가지 개선 사항을 구현했습니다.

### November 7, 2019{#20201107}

#### Improvements and Fixes

* Mendix Cloud 배포 및 운영의 안정성과 성능을 개선했습니다.

    * 이로 인해 [10월 30일에 기록된 알려진 문제](#ki20201030)도 해결되었습니다.

## October 2019

### October 30, 2019

#### Improvements

* Mendix Cloud 배포 및 운영을 업그레이드했습니다. 이제 Mendix 7 앱입니다.
* 이제 앱 상수 값을 마스킹하여 **Environment Details**의 **Model Options** 탭에서 볼 수 없도록 할 수 있습니다.
* Mendix Developer Portal 업데이트를 위한 유지보수 창이 생성된 경우 모든 **OPERATE** 및 **DEPLOY** 페이지에서 경고를 표시합니다.

<a id="ki20201030"></a>**Known Issue**

* **Environments** 페이지에서 **Production** 환경의 **Details** 버튼을 클릭하고 2단계 인증을 성공적으로 완료하면, Production 환경이 아닌 앱에 대해 나열된 **첫 번째** 환경으로 리다이렉트됩니다. (Ticket 90999)

    * 해결 방법 – **Production** 환경의 **Details**를 다시 선택하면 올바른 환경으로 이동합니다.
    * [11월 7일](#20201107) 릴리스로 해결되었습니다.

* Developer Portal에서 **OPERATE** 또는 **DEPLOY** 페이지를 열려고 하면 로그인 페이지가 나타날 수 있습니다. 페이지에 접근하려면 페이지를 강제 새로고침하거나 브라우저 캐시를 지워야 합니다.

    * [11월 7일](#20201107) 릴리스로 해결되었습니다.

### October 1, 2019

#### Improvements

* `X-Client-Certificate` 요청 헤더가 제거되었습니다. 대신 `SSL-Client-S-DN` 헤더를 사용할 수 있습니다. 자세한 내용은 [Mendix Cloud HTTP Request Headers](/developerportal/deploy/mendix-cloud-request-headers/)를 참조하세요.

## June 2019

### June 27, 2019

#### Improvements

* Custom Headers를 삭제할 때 확인 대화 상자를 추가했습니다.
* 일반적인 성능 개선을 수행했습니다.

#### Fixes

* 백업에 코멘트를 추가하지 못하던 문제를 수정했습니다. (Ticket 81993)
* Mendix Cloud v4 메트릭 페이지의 **Read documentation** 링크가 올바른 문서를 가리키도록 업데이트했습니다. (Ticket 82130)
* PEM으로 인코딩되지 않아 지원되지 않는 클라이언트 인증서를 업로드하려는 경우 적절한 피드백을 추가했습니다. (Ticket 82299)
* Mendix Cloud 노드에서 다른 환경을 유지하면서 단일 환경의 오프보딩을 방지하던 문제를 수정했습니다. (Ticket 83189)

### June 15, 2019

#### Improvements

* Mendix Cloud에서 설정한 앱 개발자가 사용할 수 있는 모든 **HTTP Request Headers**가 [Mendix Cloud HTTP Request Headers](/developerportal/deploy/mendix-cloud-request-headers/)에 문서화되어 있습니다.
* 현재 존재하는 `X-Client-Certificate` 요청 헤더는 더 이상 사용되지 않으며 이후 단계에서 제거될 예정입니다. 이 헤더에 의존하는 모든 애플리케이션은 새로운 `SSL-Client-S-DN` 헤더로 전환해야 합니다. 자세한 내용은 앞서 언급한 문서를 참조하세요.

## May 2019

### May 17, 2019

#### Fixes

* 유지보수 중 환경이 완전히 잠기도록 유지보수 창 관리에 여러 변경 사항을 적용했습니다.

### May 16, 2019

#### Improvements

* 싱글 사인온(SSO)이 활성화된 Mendix Cloud 환경에 대한 Developer Portal의 App User 관리 페이지를 재설계했습니다.

### May 9, 2019

#### Fixes

* HTTP Headers 변경으로 인해 Mendix Cloud에 배포된 앱에서 Mendix 피드백 위젯이 작동을 중단한 문제를 수정했습니다. (Ticket 83001)

### May 7, 2019

#### Improvements

* Mendix Cloud v4의 경우 Developer Portal에서 지원되는 HTTP Headers의 범위를 확장했습니다. 이전에는 *X-Frame-Options*만 지원되었습니다. 자세한 내용은 [Environment Details](/developerportal/deploy/environments-details/#http-headers)를 참조하세요.
    * 이러한 설정을 추가하거나 변경하는 경우, 변경 사항이 적용되기 전에 앱을 다시 배포해야 합니다.
* Mendix 앱 버전 7.23.1 이상의 Mendix Cloud v4 배포에 대해 AdoptOpenJDK를 지원하며, 관련 Java 버전이 Environment Details 페이지에 표시됩니다.
* 버튼 텍스트를 *Download Today's Log*에서 *Download Current Log*로 변경하여 Developer Portal에서 다운로드할 수 있는 로그를 명확히 했습니다.

#### Fixes

* 앱이 다시 연결된 후 Node Permissions에서 일부 팀 구성원이 표시되지 않던 문제를 해결했습니다(Tickets 70285, 79708, 79824, 80557, 81713, 82591).

### May 3, 2019

#### Improvements

* Mendix **Free Edition**을 출시했습니다. 이를 통해 Mendix Cloud에 배포된 Free App에서 10명의 지정 사용자 제한이 제거됩니다. 기존 앱에서 *Free Edition*을 활용하려면 앱을 다시 배포해야 합니다.

## March 2019

### March 29, 2019

#### Improvements

* Mendix Cloud v4에 *Flexible Environments*를 도입했습니다. 이제 라이선스된 노드에 세 개 이상의 환경을 가질 수 있습니다. 자세한 내용은 [여기](/developerportal/deploy/mendix-cloud-deploy/#flexible-environments)에서 확인할 수 있습니다. 세 개 이상의 환경이 필요하면 [Mendix Support](/support/)에 문의하세요. Flexible Environments의 기능은 다음과 같습니다:
    * 세부 정보를 확인하려는 환경을 검색할 수 있습니다
    * Technical Contact가 환경 이름을 변경할 수 있습니다
    * Technical Contact가 환경 순서를 변경할 수 있습니다
* Flexible Environments 지원의 일환으로 다음과 같은 변경 사항이 적용되었습니다:
    * Developer Portal을 통해 애플리케이션을 배포할 때 대상 환경을 선택할 수 있습니다
    * 메트릭, 로그, 백업 등을 확인할 때 직접 환경을 클릭하는 대신 드롭다운을 사용하여 환경을 선택해야 합니다

#### Other Improvements

* API를 사용하는 기존 방법에 더해 Developer Portal을 통해 태그를 관리하는 기능을 추가했습니다.

### March 7, 2019

#### Fixes

* 환경이 초기화되기 전에 추가된 사용자 정의 도메인이 환경에 바인딩되지 않던 문제를 수정했습니다. (Tickets 78324, 76159, 76439, 77366, 77504, 78324, 78484)
* 환경에 MDA를 전송했지만 환경을 재시작하지 않고 프로세스를 취소한 후에도 Environment Details의 "Running Since" 값이 업데이트되던 문제를 수정했습니다. (Ticket 76893)
* MDA 패키지 빌드 시 불명확한 애플리케이션 버전 번호 문제를 수정했습니다. 값을 더 정확하게 나타내기 위해 "App latest tag"와 "Branch latest tag"를 각각 "App highest tag"와 "Branch highest tag"로 대체했습니다. (Ticket 78699)
* 일부 Mendix Cloud v3 프로덕션 환경에서 Developer Portal에 라이선스 정보가 잘못 표시되던 문제를 수정했습니다. (Ticket 78229, 80336)

## February 2019

### February 6, 2019

#### Fixes

* 일부 샌드박스가 중지된 후 재개되지 못하던 문제를 해결했습니다.
* ACS(AppCloudServices)가 있는 앱이 Web Modeler를 사용하여 배포되지 못하던 문제를 수정했습니다. (Ticket 76888)

## January 2019

### January 28, 2019

#### Improvements{#tls}

**Mendix Cloud v4에서 TLS v1.0 및 v1.1 비활성화**

* Mendix Cloud v4 인프라에 TLS v1.2 이상을 지원하지 않는 수신 연결이 작동을 중단하도록 변경을 구현했습니다. 이는 사실상 TLS v1.0 및 v1.1이 비활성화되었으며, Mendix Cloud v4가 다시 [SSL Labs에서 A+ 등급](https://www.ssllabs.com/ssltest/index.html)을 받았음을 의미합니다.

### January 3, 2019

#### Fixes

* 일부 Mendix Cloud v4 및 v3 애플리케이션의 일부 애플리케이션 상수에 대한 잘못된 값 관련 문제를 수정했습니다. (Tickets 77302, 77390, 77505, 77797)
* 일부 Mendix Cloud v3 사용자가 애플리케이션의 Java 버전을 변경할 수 없던 문제를 해결하고 수정했습니다. (Tickets 77251, 77652)
