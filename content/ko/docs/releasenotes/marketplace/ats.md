## 2.24.0

**Release date: April 8, 2021**

### Mendix 9 지원

이 릴리스와 함께 ATS는 Mendix 9로 빌드된 앱 테스트를 공식적으로 지원합니다. 이에는 테스트 단계 녹화 및 테스트 실행이 모두 포함됩니다.

### 개선 사항

* 단계를 재사용 가능한 액션으로 추출할 때 확인 대화 상자를 추가했습니다. 이는 실수로 액션을 추출하는 것을 방지하기 위한 것입니다.

### 수정 사항

* 값이 500자 이상을 허용하지 않는 버그를 수정했습니다. (CP13883)
* 사용자 정의 액션의 입력 매개변수를 기반으로 테스트 단계의 값을 설정할 때 오류가 발생하는 버그를 수정했습니다. (CP13922)
* 새로 온보딩된 앱에 대해 ATSelenium이 Selenium 공급자로 사용할 수 없는 버그를 수정했습니다.
* 특수 HTML 문자가 포함된 경우 테스트 단계의 값이 올바르게 표시되지 않는 버그를 수정했습니다.
* Boolean, any 및 enumeration 필드에 대한 자동 제안이 가능한 모든 상수 값을 제안하지 않는 버그를 수정했습니다.

## 2.23.0

**Release date: March 2, 2021**

### 다크 테마 지원

ATS 팀에서는 라이트 테마와 다크 테마에 대한 치열한 토론을 자주 합니다. 다행히도 이 새로운 기능으로 선호하는 테마를 직접 선택할 수 있습니다.

프로필 이미지를 클릭하고 다음 옵션 중 하나를 선택하여 테마를 변경할 수 있습니다:

* **System** (기본값) – 운영 체제 기본 설정에 맞추기
* **Dark** – 다크 테마 사용 (새로운 기능!)
* **Light** – 라이트 테마 사용 (ATS 2.0 이후 사용해 온 표준 테마)

### 항목 잠금

웹 기반 도구로서 ATS에는 많은 장점이 있습니다. 우선, ATS를 설치할 필요가 없습니다. 그러나 이에는 로컬 리포지토리 시스템이 없다는 것과 같은 일부 과제도 있습니다. 이는 변경 사항이 프로젝트 전체 리포지토리에 직접 적용됨을 의미합니다. 따라서 두 테스터가 테스트 케이스에서 작업하면 테스트 단계가 순서가 맞지 않는 등의 이상한 일이 발생할 수 있습니다.

이러한 사고를 방지하기 위해 더 이상 두 사용자가 테스트 케이스를 동시에 편집할 수 없습니다. 다른 사용자가 현재 편집 중인 테스트 케이스를 열려고 하면 ATS가 이를 중지하고 명확한 메시지를 표시합니다. 테스트 스위트 및 사용자 정의 액션도 마찬가지입니다.

### 개선 사항

* **Extract action** 대화 상자가 혼동을 방지하기 위해 **Set details**로 이름이 변경되었습니다.
* 웹 요소를 반환하는 모든 함수의 출력 매개변수 이름이 더 일관되도록 변경되었습니다. ATS는 다른 유형의 웹 요소를 구분하지 않으며, 새로운 이름이 이를 더 명확하게 하기를 바랍니다.
* 몇 가지 스타일링 문제를 수정했으며, 특히 반응형 모드에 대한 지원을 수정했습니다. 작은 화면에서는 사이드 메뉴가 햄버거 메뉴를 통해 토글할 수 있는 슬라이드 오버로 축소됩니다. 이의 주요 용도는 녹화 화면으로, 녹화와 녹화 중인 앱을 나란히 놓고 싶을 수 있습니다.
* 리포지토리의 **Import**/**New** 버튼이 단일 액션 버튼 대신 두 개의 별도 버튼으로 분리되었습니다.

### 수정 사항

* 예약된 테스트가 오류 메시지 없이 시작되지 않는 버그를 수정했습니다.
* 데이터 세트 이름 및 설명에 대한 변경 사항이 때때로 올바르게 저장되지 않았습니다. 이로 인해 연결된 테스트 케이스가 실패하기도 했습니다. 두 가지 문제가 모두 수정되었습니다.
* 버그로 인해 초기 단계에서 실패한 작업이 로그를 표시하지 않았습니다. 이것이 수정되었습니다.
* **Value** 드롭다운 메뉴가 간헐적으로 닫혔습니다. 이를 가능한 한 방지하기 위해 위젯을 변경했습니다.
* 사용자 정의 액션인 이전 단계의 출력 값을 사용하는 단계가 있는 테스트 케이스에서 가져오기가 실패하는 버그를 수정했습니다.
* **Log off** 버튼이 작동하지 않고 대신 JSON을 표시하는 문제를 수정했습니다. 이제 먼저 현재 ATS 세션에서 사용자를 로그아웃한 다음 Developer Portal로 리디렉션하여 올바르게 작동합니다.
* 문서 및 데스크톱 레코더에 대한 링크가 모두 수정되었습니다.

## 2.22.0

**Release date: January 19, 2021**

### 개편된 값 입력 위젯

사용자의 피드백 증가로 인해 테스트 단계 값을 입력하는 데 사용되는 위젯을 개편했습니다. 주요 변경 사항은 다음과 같습니다:

* 주요 속도 향상 – 매번 값을 확인하는 대신 위젯이 이제 가능한 값을 캐시하여 더 유창한 경험을 제공합니다.
* 리터럴 값을 편집할 수 있습니다 – 선택한 값이 리터럴 문자열(예: `button1`)인 경우 값을 편집하기 위해 클릭하면 이 리터럴 값이 유지되어 제자리에서 쉽게 편집할 수 있습니다(즉, `button1`을 `button2`로 변경하는 것이 이전보다 훨씬 쉬워졌습니다. 이전에는 전체 문자열을 다시 입력해야 했습니다).
* <kbd>Enter</kbd>를 누르면 현재 선택된 값이 저장됩니다 – 더 이상 권장 값을 수동으로 클릭할 필요가 없으며, <kbd>Enter</kbd>를 누르면 자동으로 선택됩니다.

이러한 개선 사항이 ATS 작업 속도를 높이는 데 도움이 되기를 바랍니다.

### 더 많은 경고로 더 적은 오류

ATS의 테스트 케이스는 매개변수, 데이터 세트 및 이전 테스트 단계에서 오는 값으로 동적입니다. 이 릴리스에서는 테스트 단계를 삭제할 때 해당 출력(즉, 반환 값)이 후속 단계에서 사용되지 않는지 확인하기 위한 검사를 모두 추가했습니다. 값이 사용되는 경우 작업을 취소할 수 있는 경고가 표시됩니다. 데이터 세트 및 사용자 정의 액션의 매개변수를 제거하거나 삭제할 때도 동일하게 적용됩니다. 테스트 단계를 비활성화하는 것도 이 검사에 포함됩니다.

### 개선 사항

* ATS는 이제 단계가 사용자 정의 액션인지 및/또는 단계에 사전 조건이 있는지를 나타내는 새 아이콘을 추가합니다. 아이콘은 테스트 케이스 또는 액션을 편집할 때 표시됩니다. 또한 열 수 없는 테스트 단계에 대해서는 **Open** 버튼이 더 이상 표시되지 않습니다.
* 액션, 테스트 케이스 및 테스트 스위트를 편집할 때 성능을 향상시키기 위한 아키텍처 변경을 수행했습니다.
* ATS는 이제 테스트 단계를 편집할 때 입력 매개변수와 출력 매개변수를 명확하게 분리합니다. 출력 매개변수 유형도 표시되며 혼란스러운 **Required/optional** 레이블이 선택적 출력 값에 대해 **Possibly empty**로 변경되었습니다.
* 다른 단계의 출력 값을 참조하는 테스트 단계에 대한 값을 선택할 때 ATS는 이제 해당 단계가 비활성화되었는지 표시합니다. 비활성화된 테스트 단계의 출력 값은 항상 `empty`입니다.

### 수정 사항

* 비활성화된 테스트 단계를 복사하면 활성화된 테스트 단계가 되는 버그를 수정했습니다.

## 2.12.0

**Release date: July 21, 2019**

### 테스트 단계 설정

ATS에서 테스트를 더 쉽게 만들고 수정할 수 있도록 하는 새로운 기능을 제공하게 되어 매우 기쁩니다. 이 릴리스에서는 다음을 수행할 수 있는 테스트 단계 설정을 추가합니다:

* 테스트 단계 비활성화
* 통과하지 못하면 실행 중단
* 테스트 케이스에서 assert 부정

#### 테스트 단계 비활성화

이 기능을 사용하면 삭제하지 않고 테스트 단계를 일시적으로 비활성화할 수 있습니다. 이는 코드 줄을 주석 처리하는 것과 유사합니다. 특정 단계 없이 테스트 스크립트가 어떻게 동작하는지 테스트하는 데 사용하세요. 단계가 필요한 것으로 판명되면 다시 활성화하기만 하면 됩니다. 이 기능은 테스트 스위트, 테스트 케이스 및 액션에서 사용할 수 있습니다.

#### 통과하지 못하면 실행 중단

대규모 테스트 스위트의 시작 부분에 특정 데이터 및 기타 조건을 만드는 일종의 설정 스크립트가 필요한 경우를 자주 보았습니다. 이 스크립트가 실패하면 테스트 스위트의 실행을 더 이상 계속하는 것이 의미가 없습니다. 이것이 바로 이 기능을 만들 때 생각한 시나리오입니다. 단계가 통과하지 못하면 중단으로 플래그가 지정되면, 통과하지 못한 경우 후속 테스트 단계는 실행되지 않습니다. 이를 통해 시간과 비용을 절약합니다. 이 기능은 순차 실행이 있는 테스트 스위트에서만 사용할 수 있습니다.

#### 테스트 결과 부정

대부분의 경우 테스트는 페이지의 요소 존재를 assert하고 텍스트 또는 숫자가 예상 값을 가지고 있는지 assert합니다. 그러나 때때로 반대를 assert해야 할 필요가 있습니다(즉, 요소가 페이지에 없음을 assert하거나 텍스트가 특정 값을 가지지 않음을 assert). 이제 부정 토글로 가능합니다.

부정할 수 있는 모든 함수의 전체 목록은 다음과 같습니다:

* `Logic`
    * `Assert Contains String`
    * `Assert endsWith`
    * `Assert startsWith`
    * `Assert equalTo` – `Assert not equalTo`, `assert null`, `assert not null`, `assert not true`, `assert not false`는 모두 `Assert equalTo`를 위해 지원 중단되었습니다. 이러한 함수가 테스트 케이스 또는 액션에서 사용된 경우 올바른 `Negate` 값으로 `Assert equalTo`로 자동 대체되었습니다
    * `Assert equalToIgnoringCase`
    * `Assert equalToIgnoringWhitespace`
* `Web`
    * `Assert Element Attribute Equals`
    * `Assert Element Matches Selector`
    * `Find Element`
    * `Find Element By Id`
    * `Find Element By CSS`
    * `Find Element By Sizzle`
* `Mendix`
    * `Assert Current Page Title`
* `Widget:Find`
    * `Find Checkbox Set Selector`
    * `Find DataGrid Row`
    * `Find/Assert Dialog`
    * `Find Grid Selector`
    * `Find Item/Row`
    * `Find Menu Item`
    * `Find Selected Item/Row`
    * `Find Widget Child Node`
    * `Find/Assert Widget`
* `Widget:Assert`
    * `Assert Active Tab Name`
    * `Assert Checkbox Set Selector Value`
    * `Assert Checkbox Value`
    * `Assert Grid Selector Value`
    * `Assert Simple Checkbox Set Selector Value`
    * `Assert Validation Message`

#### 개선 사항

* **Set Value**의 타임아웃을 60초에서 5초로 줄였습니다. 이를 통해 위젯을 찾을 수 없거나 편집할 수 없을 때 테스트가 더 빨리 실패합니다.

#### 수정 사항

* 매개변수가 없는 테스트 단계에 대해 함수 이름이 표시되지 않는 버그를 수정했습니다(테스트 케이스 및 액션).
* 드문 경우 테스트 케이스에 대한 로그가 누락되는 버그를 수정했습니다.
* 로그인 후 페이지 로드를 ATS가 대기하지 않는 버그를 수정했습니다.

BrowserStack 측의 새로운 기능은 다음과 같습니다:

* ATS의 다른 앱이 BrowserStack에서 다른 **Projects**로 표시됩니다. 이는 동일한 BrowserStack 계정을 사용하여 여러 앱을 테스트하는 경우 유용합니다.

* BrowserStack의 개별 테스트 케이스 실행(즉, **Sessions**)이 이제 작업 이름 대신 테스트 케이스 이름을 올바르게 표시합니다. 데이터 세트가 첨부된 테스트 케이스의 경우 테스트 케이스 이름 뒤에 데이터 세트 레코드의 인덱스가 추가됩니다.
* BrowserStack의 테스트 케이스 실행이 이제 ATS의 결과를 표시합니다.

* BrowserStack에서 실행된 각 테스트 케이스에 대해 BrowserStack의 Selenium 세션에 대한 링크를 추가했습니다. 녹화 비디오가 ATS에서 로드되지 않는 경우 또는 BrowserStack 로그를 보려는 경우 이를 사용할 수 있습니다. 링크는 **Recording** 탭 아래에서 찾을 수 있습니다.
* BrowserStack에서 ATS로 더 쉽게 탐색할 수 있도록 작업 GUID로 작업을 조회하고 BrowserStack 세션 ID로 개별 테스트 케이스 로그를 조회하는 옵션을 추가했습니다. 둘 다 **Test Runs** 페이지의 **Jobs** 탭에서 찾을 수 있습니다.

### 기타 개선 사항

* ATS의 인기 증가에 따라 사용자가 더 큰 테스트 스위트를 만들고 있어 ATS 백엔드에 부하가 걸리고 있었습니다. 따라서 테스트 실행 결과 처리를 위한 여러 최적화를 출시합니다. 이를 통해 모든 사용자에게 성능이 향상될 것으로 예상하지만, 특히 대규모 테스트 스위트를 가진 사용자에게 향상될 것입니다.

### 수정 사항

* 실패한 테스트 스위트를 다시 실행할 때 구성이 테스트 스위트의 원래 실행에서 사용된 구성 대신 해당 테스트 스위트에 대해 가장 최근에 사용된 구성으로 기본 설정되었습니다. 이것이 이제 수정되었습니다.

## 2.9.4

**Release date: December 4, 2018**

### 개선 사항

* App Settings 페이지에서 앱 역할을 새로 고침하는 옵션을 추가했습니다. 새로 고침 버튼을 클릭하면 현재 앱의 모든 사용자에 대한 앱 역할이 Developer Portal에서 조회되고 ATS의 역할 업데이트에 대한 표준 규칙에 따라 ATS에서 업데이트됩니다. Developer Portal의 해당 프로젝트에 더 이상 접근 권한이 없는 사용자는 앱에서 제거됩니다. Developer Portal에서 앱의 새 멤버는 ATS에서 앱의 멤버가 되기 전에 ATS에 로그인하고 이용 약관에 동의해야 합니다.
* ATS에서 테스트 결과가 처리되는 방식을 계속 최적화했습니다. 이를 통해 테스트 결과를 확인하는 데 걸리는 지연이 줄어들 것으로 예상합니다.

### (잠재적) 호환성 변경 사항

긴 on-change Microflow(>500 ms)로 인한 불안정한 테스트에 대한 불만으로 인해 **Set Value** 함수의 동작을 변경하기로 결정했습니다.

이전 버전에서 Set Value 함수는 입력 필드에 값을 입력하고 해당 필드에 포커스를 유지했습니다. 따라서 on-change 및 on-leave Microflow는 나중 테스트 단계에서 페이지의 다른 요소에 포커스가 맞춰질 때까지(예: 클릭을 통해) 트리거되지 않았습니다. 이는 자연스러운 사용자 동작이라고 느꼈기 때문에 의도적으로 수행되었습니다(즉, 다른 요소와의 상호 작용이 발생할 때까지 포커스를 유지).

ATS 버전 2.9.4부터 Set Value 함수는 값을 설정한 후 위젯의 포커스를 해제하고 on-change 및 on-leave Microflow가 완료될 때까지 대기한 후 테스트 케이스의 다음 단계로 진행합니다. on-change Microflow가 사용될 때 대기를 통해 테스트가 더 안정적이 되기를 바랍니다. 이러한 Microflow는 테스트를 진행하기 전에 실행이 완료되었음을 보장하기 때문입니다.

이 변경으로 기존 테스트에 문제가 발생할 것으로 예상하지 않습니다. 그러나 업데이트 후 Set Value 함수와 관련된 이상한 동작이 발견되면 Support 티켓을 제출하여 알려주세요.

## 2.9.3

**Release date: October 15, 2018**

### 개선 사항

* 실행된 데이터 기반 테스트 케이스에 대한 데이터 세트 레코드가 저장되는 방식을 최적화했습니다. 이를 통해 데이터 기반 테스트 케이스의 결과 처리 성능이 향상될 것으로 예상합니다.
* 비디오 녹화를 가져오는 코드를 리팩토링하여 ATS에서 녹화를 더 빨리 사용할 수 있게 했습니다.

### 수정 사항

* 버그로 인해 항목(즉, 액션, 테스트 케이스 또는 테스트 스위트)의 이름을 고유하지 않게 변경할 수 있었습니다. 이로 인해 일반 오류 메시지와 UI에서 부분적으로 변경된 이름이 표시되었습니다. 이것이 이제 수정되었으며 이름을 변경할 때 적절한 유효성 검사 메시지가 표시됩니다. 결과적으로 더 이상 항목의 이름을 인라인으로 편집할 수 없습니다. 대신 표준 저장 및 취소 옵션이 있는 대화 상자에서 수행됩니다.
* 작업 기간이 1시간보다 큰 경우 작업 기간의 형식이 올바르지 않았습니다. 이것이 이제 수정되었습니다.
* 버그로 인해 추출된 액션에서 이전 단계의 여러 출력 매개변수가 사용된 경우 액션을 추출할 수 없었습니다. 이것이 이제 수정되었습니다.
* **Find/assert data grid row** 함수에서 필수 매개변수(즉, 열 이름 또는 값)가 비어 있어도 결과를 반환하는 예기치 않은 동작을 발견했습니다. 함수의 동작을 변경하면 많은 테스트 케이스가 잠재적으로 손상될 수 있으므로 대신 이 동작에 맞게 함수의 설명을 변경했습니다. 또한 이 함수의 모든 열 이름 및 값 매개변수가 선택 사항으로 만들어졌습니다. 열 이름/값 쌍이 지정되지 않으면 첫 번째 행이 반환됩니다. 요약하면 기능적으로 변경된 것은 없으며 설명만 업데이트되었습니다.
