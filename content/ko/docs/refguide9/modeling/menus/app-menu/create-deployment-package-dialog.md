## 소개

배포 패키지는 Mendix Cloud, 다른 클라우드 제공자(예: SAP BTP) 또는 Mendix 소프트웨어를 실행하도록 구성된 서버에 배포할 수 있습니다. 개발 중에는 로컬 머신에서 배포하고 실행할 수 있지만, 다른 곳에 앱을 배포할 준비가 되면 배포 패키지를 생성해야 합니다. 일부 플랫폼에서는 배포 프로세스의 일부로 자동 수행되지만, 다른 플랫폼에서는 배포 패키지를 명시적으로 생성해야 합니다.

{{% alert color="warning" %}}
대부분의 배포 대상에는 배포할 수 있는 배포 패키지의 비압축 크기에 대한 제한이 있습니다. 예를 들어:

| 대상 | 최대 배포 패키지 크기 |
| --- | --- |
| Mendix Cloud | 1 GB |
| SAP BTP | 1.5 GB |
| Mendix on Kubernetes | 512 MB |

이것은 배포 패키지(.mda 파일)의 비압축 크기입니다. [7-Zip](https://www.7-zip.org/)과 같은 파일 아카이빙 프로그램에서 패키지 파일을 열고 파일 속성 또는 **Info**를 확인하여 비압축 크기를 찾을 수 있습니다.

안타깝게도 배포 중 로그에 표시되는 오류에서 패키지 크기가 문제인지 항상 명확하지는 않습니다. 하지만 앱 배포에 문제가 있는 경우 가능한 원인 중 하나로 패키지 크기를 확인해야 합니다.
{{% /alert %}}

## 버전 지정

여기서 버전이 지정된 배포 패키지를 생성할지 여부를 결정할 수 있습니다.

버전이 지정된 배포 패키지는 Team Server에 보관된 특정 리비전의 새로운 다운로드에서 빌드됩니다. 이는 항상 출처를 추적하고 다시 생성할 수 있음을 의미합니다. Mendix는 매우 타당한 이유가 없는 한 버전이 지정된 배포 패키지를 생성할 것을 권장합니다.

버전이 지정되지 않은 배포 패키지는 디스크의 로컬 앱을 기반으로 하며 특정 리비전으로 추적할 수 없습니다.

## 버전 지정 배포 패키지 옵션

버전 지정 배포 패키지를 생성하는 경우 아래에 설명된 정보를 입력해야 합니다. 버전 관리에 대한 자세한 내용은 [Version Control](/refguide9/version-control/)을 참조하십시오.

### Development Line

배포 패키지를 생성할 **Development line**을 선택하십시오. 메인 라인 또는 모든 Branch Line을 선택할 수 있습니다. 예를 들어 유지보수 Branch Line에서 구현한 수정 사항을 온라인에 적용하려면 해당 Branch Line에서 패키지를 생성합니다. 또는 앱의 다음 주요 버전을 배포할 준비가 되었기 때문에 메인 라인에서 배포 패키지를 생성합니다.

### Revision

배포 패키지를 생성할 선택된 Development Line의 **Revision**을 선택하십시오. 최근에 개발한 기능을 제외하려는 경우 최신 리비전을 원하지 않을 수 있습니다.

### New Version

배포 패키지의 **New version**을 선택하십시오. 버전은 4개의 숫자로 구성됩니다: 주 버전, 부 버전, 패치 및 리비전. 리비전은 고정되며 **Revision**에서 선택한 리비전에 의해 결정됩니다.

다른 숫자는 자유롭게 선택할 수 있지만 번호 매기기에 규칙을 사용하는 것이 좋습니다. 주 버전에는 일반적으로 주요 새 기능 또는 기존 기능의 재작성이 포함됩니다. 부 버전에는 작은 새 기능과 수정이 포함됩니다. 패치는 사소한 문제를 해결하며 앱의 데이터 모델을 변경해서는 안 됩니다. 패치 릴리스는 데이터 변경 없이 다른 패치 릴리스와 상호 교환 가능해야 합니다.

Studio Pro는 패키지를 생성한 최신 버전(있는 경우)을 표시합니다. 사용하는 규칙에 따라 주, 부 또는 패치를 증가시킬 수 있습니다.

### Description

이 배포 패키지에 대한 사용자 정의 **Description**을 입력할 수 있습니다. 패키지를 빠르게 인식할 수 있도록 하는 참조용입니다. Mendix Portal에서 버전 번호와 함께 이 설명이 표시됩니다.

## 파일 이름

버전 지정 및 비버전 지정 배포 패키지 모두 배포 패키지가 저장될 위치를 알아야 합니다. 이는 **File name** 필드에 표시됩니다. 이 필드는 편집할 수 없습니다.

모든 패키지는 앱 디렉토리 내의 **releases** 디렉토리에 배치됩니다. 이 디렉토리는 자동으로 무시되므로 이러한 패키지는 리포지토리에 커밋되지 않습니다. 배포 패키지는 항상 다시 생성할 수 있으므로(원래 사용한 Studio Pro 버전 사용) Team Server에 올릴 필요가 없습니다.
