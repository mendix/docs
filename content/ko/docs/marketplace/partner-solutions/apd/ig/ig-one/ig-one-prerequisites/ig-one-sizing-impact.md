적절한 하드웨어에서의 부하 테스트 결과, CPU 사용량 증가가 매우 수용 가능한 수준인 것으로 나타났습니다. Trap Tool과 Statistics Tool만 실행할 때 몇 퍼센트 정도이며, Performance Tool이 SQL 문을 기록할 때는 5%를 약간 넘지만 CPU가 30%, 50%, 70%일 때에도 10% 미만의 CPU 사용량 증가를 보입니다.

메모리 및 디스크 사용량은 다음 표에서 도구별로 분석됩니다.

| Tool | 메모리 | 디스크 사용량 |
| --- | --- | --- |
| Log Tool | 즉시 디스크에 기록하므로 일정하고 매우 적음 | 약 500,000 레코드가 1GB. 보호 옵션은 기본적으로 100,000 레코드에서 순환. |
| Trap Tool | 미리 정의된 양의 데이터만 기록하므로 일정하고 적음. 트래핑 시 별도의 스레드가 출력. 서버가 대량의 트랩을 생성하는 드문 경우에 출력 큐도 일부 메모리를 차지함. | 약 500,000 레코드가 1GB. 보호 옵션은 기본적으로 100,000 레코드에서 순환. |
| Statistics Tool | Microflow당 1개의 레코드이므로 일정하고 적음 | 적음, 일일 1,000개 Microflow의 경우 3년간 1,000,000 레코드 미만으로 약 3GB. 정리 옵션은 마지막 1년만 유지하도록 구성되어 있으며, 이 예에서는 1GB. |
| Performance Tool | 보호 기능이 제거되면 메모리를 가득 채울 수 있음. 따라서 도구에 보호 조치가 있음. 512MB에서 평균 8개 액션이 있는 50,000개 Microflow 또는 50,000개 SQL 문을 포함한 40,000개 Microflow를 저장할 수 있음 | 액션 및 관계 테이블을 포함한 50,000개 Microflow가 450MB. 50,000개 SQL 문이 100MB(공식은 대략 Microflow당 1kb, 액션당 1kb, SQL당 2kb). Performance Tool 사용은 사례별로 이루어지므로 정리도 마찬가지임. 시스템은 1개월보다 오래된 모든 트레이스를 자동으로 정리할 수 있음. |
| Measurement Tool | 측정당 하나의 스레드가 소량의 메모리를 차지 | 약 1,000,000개 측정이 100MB. 5초마다 CPU 및 메모리에 대한 기본 측정을 수행하면 연간 약 20,000,000개 레코드 또는 대략 2GB. 시스템은 1년보다 오래된 모든 트레이스를 자동으로 정리할 수 있음. |
| **권장 예약** | 512 MB | 1 GB |
