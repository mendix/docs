## 소개

배포 패키지는 Mendix Cloud, 다른 클라우드 제공업체(예: SAP BTP) 또는 Mendix 소프트웨어를 실행하도록 구성된 서버에 배포할 수 있습니다. 개발 중에는 로컬 머신에서 배포하고 실행할 수 있습니다. 하지만 앱을 다른 곳에 배포할 준비가 되면 배포 패키지를 생성해야 합니다. 일부 플랫폼에서는 배포 프로세스의 일부로 자동으로 수행되지만, 다른 플랫폼에서는 배포 패키지를 명시적으로 생성해야 합니다.

{{% alert color="warning" %}}
대부분의 배포 대상에는 배포할 수 있는 배포 패키지의 압축 해제 크기 제한이 있습니다. 다음은 몇 가지 예입니다:

| 대상 | 최대 배포 패키지 크기 |
| --- | --- |
| Mendix Cloud | 1 GB |
| SAP BTP | 1.5 GB |
| Mendix on Kubernetes | 1024 MB |

이것은 배포 패키지(*.mda* 파일)의 압축 해제 크기입니다. [7-Zip](https://www.7-zip.org/) 같은 파일 압축 프로그램에서 패키지 파일을 열고 파일 속성 또는 **Info**를 확인하면 압축 해제 크기를 확인할 수 있습니다.

안타깝게도 배포 중 로그에 표시되는 오류만으로는 패키지 크기가 문제인지 항상 명확하지 않습니다. 하지만 앱 배포에 문제가 있는 경우 패키지 크기가 하나의 가능한 원인입니다.
{{% /alert %}}

## 버전 지정

여기에서 버전이 지정된 배포 패키지를 생성할지 여부를 결정할 수 있습니다.

버전이 지정된 배포 패키지는 Team Server에 보관된 특정 리비전의 새로운 다운로드에서 빌드됩니다. 이는 항상 출처를 추적하고 다시 생성할 수 있음을 의미합니다. Mendix는 특별한 이유가 없는 한 버전이 지정된 배포 패키지를 생성할 것을 권장합니다.

버전이 지정되지 않은 배포 패키지는 디스크의 로컬 앱을 기반으로 하며 특정 리비전으로 추적할 수 없습니다.

## 버전이 지정된 배포 패키지 옵션

버전이 지정된 배포 패키지를 생성하는 경우 아래에 설명된 정보를 입력하세요. 버전 관리에 대한 자세한 내용은 [Version Control](/refguide10/version-control/)을 참조하세요.

### Development Line

배포 패키지를 생성할 **Development line**을 선택하세요. 메인 라인 또는 브랜치 라인을 선택할 수 있습니다. 예를 들어, 메인터넌스 브랜치 라인에서 구현한 수정 사항을 온라인에 배포하려는 경우 해당 브랜치 라인에서 패키지를 생성할 수 있습니다. 또는 다음 주요 버전의 애플리케이션을 배포할 준비가 되었다면 메인 라인에서 배포 패키지를 생성할 수 있습니다.

### Revision

배포 패키지를 생성할 선택된 development line의 **Revision**을 선택하세요. 일반적으로 최신 리비전을 선택하지만, 필요한 경우 이전 리비전을 선택할 수도 있습니다. 예를 들어, 최근에 개발한 기능을 제외하려는 경우 이전 버전을 사용할 수 있습니다.

### New Version

배포 패키지의 **New version**을 선택하세요. 버전은 메이저 버전, 마이너 버전, 패치, 리비전의 4개 숫자로 구성됩니다. 리비전은 **Revision**에서 선택한 리비전에 의해 고정되고 결정됩니다.

다른 숫자는 자유롭게 선택할 수 있지만, 번호 매기기 규칙을 사용하는 것이 좋습니다. 메이저 버전은 일반적으로 하나 이상의 주요 새 기능이나 기존 기능의 재작성을 포함합니다. 마이너 버전은 소규모 새 기능과 수정 사항을 포함합니다. 패치는 사소한 문제를 해결하며 애플리케이션의 데이터 모델을 변경하지 않습니다. 패치 릴리스는 데이터 변경 없이 다른 패치 릴리스와 교환 가능합니다.

Studio Pro는 패키지를 생성한 최신 버전(있는 경우)을 표시합니다. 사용하는 규칙에 따라 메이저, 마이너 또는 패치 번호를 증가시킬 수 있습니다.

### Description

이 배포 패키지에 대한 사용자 정의 **Description**을 입력할 수 있습니다. 이는 패키지를 빠르게 식별할 수 있도록 순전히 참조용입니다. Mendix Portal에서는 버전 번호와 함께 이 설명이 표시됩니다.

## File Name

버전이 지정된 배포 패키지와 버전이 지정되지 않은 배포 패키지 모두 배포 패키지가 저장될 위치를 알아야 합니다. 이는 **File name** 필드에 표시됩니다. 이 필드는 편집할 수 없습니다.

모든 패키지는 앱 디렉토리 내의 **releases** 디렉토리에 배치됩니다. 이 디렉토리는 자동으로 무시되어 이러한 패키지가 저장소에 커밋되지 않습니다. 배포 패키지는 항상 (원래 사용한 Studio Pro 버전을 사용하여) 다시 생성할 수 있으므로 Team Server에 넣을 필요가 없습니다.

## 문제 해결

배포 패키지를 생성하는 데 어려움이 있는 경우 버전 관리 문제일 수 있습니다. 자세한 내용은 *Troubleshooting Version Control*의 [Cannot Create Package from a Revision](/refguide10/troubleshoot-version-control-issues/#cannot-create-package)를 참조하세요.
