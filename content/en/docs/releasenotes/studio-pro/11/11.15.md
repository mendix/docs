## 11.15.0

### New Features

#### Orthogonal Sequence Flows (Beta)

In the logic editors, we are introducing (beta) orthogonal sequence flows: flow lines that only have right corners. This is a purely visual setting and can be used to make a microflow look better.

This feature can be enabled in **Preferences** > the **New features** tab > **Microflow, Nanoflow, and Rule Editor**.

To change existing sequence flows to orthogonal, right-click them to convert several or all flows in the current document. Flows can also be converted back to be curved.

You can set the default flow shape for all new sequence flows in the **App settings** > the **Miscellaneous** tab > **Microflows**.

#### Other New Features

- We improved the UI of the **Extensions Overview** to look more modern and consistent with the rest of Studio Pro.
- We added a feature flag API under `studioPro.featureFlags.isCommandLineFlagProvided("flag-name")` so developers can check if a specified feature flag exists in the command-line arguments when running Studio Pro from the terminal.
- We added a Register Tool API under `studioPro.ai.tools.registerTool(toolDefinition)` where users can extend capabilities of Maia by letting it run their custom logic.
- We added a feature allowing users to quickly trigger a comparison of parent and child revisions.
- The **History** pane now works for apps that use a partial (blobless) clone.
- Maia now supports working with **App Settings** documents.
- Maia now supports working with **Security** documents.
- We added rules to the Best Practice Recommender that help you limit anonymous user access.  Several of these rules can automatically apply changes for you. For more information, see [Security Recommendations](/refguide/security-best-practices/).

- Message definitions are now standalone documents, making them easier to find, rename, and manage independently. Previously, message definitions were grouped inside a **Message Definitions** document. If you have apps with message definitions, they are converted automatically—each collection is replaced by a folder containing individual message definition documents.
- MCP and Skills settings are now unified in a single **Maia Settings** tab, accessible from the settings menu in the Maia chat toolbar.
- Maia can now read and understand document templates and generate a page from them.

- Maia can now start, stop, check the status of, and read the logs for your Mendix runtime.
- Maia can now create and edit the skills in your app, so you can ask it to write down a convention or update an existing skill for you.
- Strict mode is now enabled by default for new apps.
- Non-interrupting timer event sub-processes now support recurrence, allowing them to trigger repeatedly at a defined interval. This behavior is consistent with the existing recurrence support for non-interrupting timer boundary events.
- Pluggable Widgets can now be translated [using system texts](/apidocs/pluggable-widgets-client-apis/#systemtexts). Widgets can define their own or use existing texts.
- The Query Filter section in the **Database Connection** document now includes a search option, making it easier to quickly find and select relevant filter fields.

### Improvements

- We optimized the task queue polling to use fewer queries on the database and fewer resources/threads overall.
- The fix to remove renamed design properties can now be applied to all design properties in a module.
- We improved the alignment between different loading states in Maia chat.
- It is now possible to wrap `SELECT` statements and `UNION` queries with parentheses in OQL, including applying `ORDER BY`, `LIMIT`, and `OFFSET` to an individual parenthesized branch of a `UNION` in addition to (or instead of) the union as a whole. This syntax is currently only available in Java actions.
- We removed the **Other** option for single and multiple-choice questions in Maia, since all choice questions already have custom free-text responses making the **Other** option redundant.

- We added the runtime setting `OpenTelemetry.MinimalMode`. When set to `true`, it suppresses tracing spans, keeping only the ones at entry and exit sites. For now, runtime operations, user defined tasks and scheduled events are considered entry points. **Call REST service** and **Send REST request** actions are considered exit points.
- Maia now automatically saves documents it modifies, so changes are persisted immediately without requiring a manual save.
- Maia now asks for your permission before running tools that access external resources or make changes. You can allow a tool once, for the current session, or always. "Always allow" choices are remembered across restarts.
- Failing to download commit information for branches when attempting to open an app now no longer shows an error dialog.
- We now support navigating to the linked data transformer document directly from the context menu of the **Transform JSON** microflow activity.
- Maia can now see the DataTransformer transformation output, so it can verify the result and improve the script when the output is not what you asked for.
- Improved offline file storage by replacing the legacy file naming scheme with a stable, database-backed file registry. Files are no longer renamed on every synchronization, eliminating race conditions during background file access and reducing unnecessary file operations. Additionally, file contents are now only synchronized to the server when the file contents have actually changed.
- We now validate that system attributes and system associations are not assigned in `OQL INSERT` and `OQL UPDATE` statements.
- We added support for generated folders to appear in the updated documents list and to be undone.
- Maia now receives detailed information about errors inside XPaths it generates, so it can correct them more accurately.
- The module version is now displayed next to the module name in the App Explorer for all non-System modules. For more information, see the [Module Version](/refguide/module-settings/#module-version) section in **Module Settings**.
- We added a reminder to change the version number when exporting a module, as that version number is automatically used by the Marketplace.
- We improved the message shown during version control operations if Git is not installed in the system.
- The Studio Pro MCP server now reports the actual Studio Pro version instead of a hardcoded version number, so MCP clients can identify which version of Studio Pro they are connected to.
- The MCP server port setting now enforces a valid range (1025–65535); out-of-range values are automatically corrected to 1025.
- Improved memory usage in the modernized **Find Results** pane.
- We now automatically convert remaining long-lived browser sessions in offline-first web apps to [authentication tokens](/refguide/session-management/) when session data is refreshed. End-users do not have to sign in again during the conversion.


    {{% alert color="info" %}}Authentication tokens have a default validity of one year, compared with the previous long-lived session timeout of seven days of inactivity, so users may remain signed in for longer. `LongLivedSessionTimeout` no longer applies to converted sessions, so if your app relies on the previous default or a custom `LongLivedSessionTimeout`, review and configure [com.mendix.webui.AuthTokenTimeout](/refguide/custom-settings/#commendixwebuiAuthTokenTimeout). Remember that this is specified in minutes, rather than milliseconds.{{% /alert %}}
- The React client now always bundles with Rspack. Compared to Rollup, Rspack provides up to six times faster bundling and quicker incremental rebuilds than Rollup while using up to 70% less memory, reducing build and development feedback times. We removed Rollup bundling and the **App bundler** option from the **App Settings**.
- We improved the app bundle error dialog to show clearer error messages and the location of the full app bundle log.
- We optimized the deployment of snippets for React client. Apps that reuse snippets across multiple pages will see faster build times and smaller JavaScript bundle sizes.
- Pluggable widgets can now use external file entities for file and image properties, such as **Image** and **Document Viewer**.
- A new custom setting `HttpClient.ValidateAfterInactivityMs` is available to enable connection validation before reuse. (Ticket 285249)
- We simplified datasets further, by removing unsupported features (options our UI allowed you to use but that had no impact on running apps). For parameters you can now only configure the type and if it is a range (where applicable) and datasets with Java as source are automatically deleted.
- We added missing consistency errors for the unconfigured Call ML Model microflow object.
- The **Skills** button in the Maia chat input now updates automatically when a skill is added or removed, without requiring a manual sync.
- The new chat button is no longer disabled when the chat is empty.
- The **Ask** button is now enabled when an attachment is present, even without any typed text, allowing you to send attachments on their own.
- We improved keyboard navigation in the modernized **Find Results** pane. Users can now switch between result set tags with the Left and Right arrow keys. We also improved focus handling: when an operation opens **Find Results**, focus now moves directly to the results table.
- The number of open searches is now displayed as a badge in the **Find Results** tab, making it easier to see at a glance and more consistent with other panels.

### Breaking Changes

- Due to licensing issues, we no longer distribute the SAP HANA JDBC driver with the Mendix runtime. If you want to run an app with a SAP HANA database, see [SAP HANA](/refguide/saphana).

### Known Issues

* The Maia Chat pane may appear and remain functional even when Maia is disabled in **Edit** > **Preferences**.
    * Workaround: Manually close the panel when it appears.
* When using BYO LLM, switching back to the Mendix Platform provider and saving your configuration  causes reasoning and caching to stop functioning.
    * Workaround: Click **New Chat** to restore reasoning and caching. Note that **New Chat** is only available when the chat is not empty.
* The **Skills** button in Maia Chat is not visible after adding skills via Maia. It becomes visible only after restarting the app, closing the project, or starting a new chat.
    * Workaround: Click **New Chat** to make the **Skills** button appear without requiring a full restart. Note that **New Chat** is only available when the chat is not empty.
* The `mx.exe module-import replace` and `mx.exe module-import update` commands will not rescue storage GUIDs after a module update, which will result in data loss.
