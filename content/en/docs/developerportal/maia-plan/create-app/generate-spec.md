## Introduction

Maia translates your defined scope into a concrete set of specs, where each spec corresponds to a specific capability.

1. After you click **Create Specs**, the **Spec** window is displayed, and Maia starts populating it with the proposed specs based on the project scope. The generated specs are listed in the left-hand pane. Each spec is made up of several requirements. For project management purposes, a spec corresponds to an epic, and a requirement corresponds to a story.

2. While the project plan is being generated, you can click **Previous** to return to the **Scope** window. Any changes you have made are automatically saved.
   
3. Once the scope is generated, you can see the following information for each spec:

    * **Dependencies** – Any dependencies that the current spec might have on other specs.
    * **User Groups** – The roles which are impacted by the current spec.
    * **Core Intent** – The main purpose and action items of the current spec.
    * **Scope**:

        * **In Scope** – These are the items that are in scope for the current spec.
        * **Out of Scope** – These are the items that will not be developed as part of the current spec. Maia also displays the spec which will handle each item.

    * **Requirements** – A list of requirements that make up the current spec. These are logically generated by the Maia agent, and include the following details:

        * **Acceptance Criteria** – The criteria that need to be checked in order to deem the requirement successful.
        * **Scenarios** – The use cases that the requirement covers.    
        You can edit any of these details.

    You can edit these items, and add or remove as necessary. 

4. After the project scope is fully generated and you have made any necessary changes, click one of the available options:
   
   * **Open in Jira** – Start managing the project in Jira.
   * **Build in Maia Make** – Open the project in Studio Pro's Maia Make.

After all the specs are generated, you can go back to the scope view by clicking **Previous**. However, if you edit the scope, all the specs are regenerated.

{{% alert color="warning" %}} Maia Chat is not available for specs.{{% /alert %}}

For details on the next steps, refer to [Starting the Development](/developerportal/maia-spec/start-development/).

## Recommended Marketplace Components {#recommender}

{{% alert color="warning" %}}
This feature is in Public Beta. For more information, refer to [Release Status](/releasenotes/release-status/).
{{% /alert %}}

Maia identifies approved Marketplace components that can accelerate your development. If Maia finds components that can help you implement a specific story, they are displayed in the following places:

* At the epic level, as a number. Example: *1 Resource*.
* At the user story level, in the side panel. From here, you can perform the following actions:

    * If you want more details about the component, click it to access its page in the Marketplace.
    * If you do not want a component to be used, delete it by clicking the trash can icon.

If your company has company-approved components, Maia only returns company-approved components from the Public and Private Marketplace.    
If your company does not have company-approved components, Maia returns the following types of components:

* Platform-supported components
* All Private Marketplace components
