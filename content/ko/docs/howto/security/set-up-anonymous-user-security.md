## 소개

애플리케이션에 대한 익명 접근을 설정할 때는 사용자에게 접근을 허용하는 위치에 주의해야 합니다. 전체 애플리케이션을 공개적으로 접근 가능하게 만들지 않도록 몇 가지 지침이 있습니다.

익명 사용자 역할을 만들 때는 항상 가능한 한 적은 접근 권한을 부여해야 합니다. 따라서 이름이 지정된 사용자 계정의 모듈 규칙을 재사용하면 안 됩니다. 모듈 규칙을 재사용하는 것이 더 빠를 수 있지만, 익명 사용자에게 애플리케이션의 정보에 대한 너무 많은 접근을 허용하기가 훨씬 쉬워집니다. 익명 사용자를 사용하는 경우, 객체에 대한 변경 사항은 실제 사용자를 추적할 수 없습니다. 사용자가 익명이었고 더 이상 존재하지 않기 때문입니다.

**이 사용 방법을 완료하면 다음을 수행할 수 있습니다:**

* 비영구 객체에 대한 접근 설정
* 익명 사용자에게 읽기 및 쓰기 접근 권한 부여

## 비영구 객체

비영구 객체에 대한 접근을 설정할 때, 지정하는 보안 규칙은 기능적으로 필요한 것이어야 합니다. 비영구 객체는 객체를 생성한 사용자의 세션 캐시에서만 존재합니다. 따라서 익명 사용자는 자신을 위해 또는 자신에 의해 특별히 생성되지 않은 정보에 절대 접근할 수 없습니다. 그러나 영구 객체의 경우는 완전히 다른 상황입니다.

## 쓰기 접근

익명 사용자에게 애플리케이션의 모든 필드에 대한 쓰기 접근 권한을 부여하는 경우, 인스턴스 접근도 함께 지정해야 합니다. 익명 사용자가 특정 객체 타입의 모든 레코드를 변경할 수 있도록 허용하는 경우는 거의 없습니다. 익명 사용자는 일반적으로 방금 생성한 레코드만 변경할 수 있어야 합니다. 따라서 다음 접근 규칙을 지정해야 합니다: `[System.Owner='[%CurrentUser%]']` 이렇게 하면 익명 사용자는 세션 동안 방금 생성한 레코드만 변경할 수 있습니다.

## 읽기 접근

익명 사용자가 특정 기본 데이터 테이블에 접근해야 하거나 개요에서 사용자 이름이 필요한 경우, 익명 사용자는 해당 Entity에 대한 읽기 접근이 필요합니다. 그러나 항상 이 접근을 제한해야 합니다. 사용자가 모든 필드에 접근할 필요가 없다면, 접근 권한을 부여하지 마세요. 전체 읽기 접근 권한을 가진 익명 사용자를 보면, 항상 더 적은 접근으로도 가능한지 확인하세요.

## 보안 검토

애플리케이션을 검토하고 익명 사용자를 점검할 때, 가장 자주 빨간 깃발(애플리케이션이 안전하지 않음을 나타내는)을 트리거하는 세 가지가 있습니다:

* 일반 애플리케이션 사용자의 모듈 역할을 재사용하는 익명 사용자 역할
* 쓰기 접근은 있지만 인스턴스 접근 XPath 제약 조건이 없는 익명 모듈 역할
* Entity에 대한 전체 읽기 접근 권한을 가진 익명 모듈 역할

이러한 상황 중 하나라도 보이면, 이러한 매개변수가 달성하려는 목표에 필요한지 신중하게 고려해야 합니다.

**페이지에서 데이터를 제한하는 것이 애플리케이션을 안전하게 만들지 않는다는 것을 항상 인지하세요.** 애플리케이션을 안전하게 만드는 유일한 방법은 모든 Entity에 접근 규칙을 지정하고 볼 수 있도록 허용되는 객체의 인스턴스를 제한하는 것입니다.

모든 사용자는 URL에 메시지를 게시할 수 있는 도구를 다운로드하고 플랫폼에 JSON 쿼리를 전송하여 API에 직접 통신할 수 있습니다. 이는 브라우저와 서버 간의 통신을 시뮬레이션합니다. 서버는 세션 내에서 허용되는 것과 일치하는 한 누가 메시지를 보내는지 상관하지 않기 때문입니다.

## 모범 사례

익명 접근이 있는 경우, 가능한 한 적은 수의 Entity에 대한 접근을 제한하고 단순히 항목을 선택하는 것이라면 모든 속성에 대한 전체 읽기 접근 권한을 부여하지 마세요. 예를 들어, 익명 사용자가 앱 이름을 볼 수 있도록 허용하는 경우, 전체 Entity가 아닌 앱 이름에 대한 읽기 접근만 부여하세요.

익명 사용자에게 객체를 변경할 수 있는 접근 권한을 부여해야 하는 경우, 항상 인스턴스 접근도 함께 적용하세요. 익명 사용자는 Entity의 모든 레코드에 대한 쓰기 접근 권한을 절대 가져서는 안 됩니다.

내비게이션 또는 페이지 표시를 제한하는 것은 보안과 같은 것이 아닙니다. 모든 데이터는 Platform API에 직접 통신하여 접근할 수 있으며, 보안 모델에 따라 표시되는 모든 것은 서버에 올바른 메시지를 전송하여 접근할 수 있습니다. UI에서 데이터를 제한하는 것이 데이터에 접근할 수 없음을 의미하지 않습니다. 인스턴스 접근 규칙만이 할 수 있는 것과 할 수 없는 것을 보장합니다.
